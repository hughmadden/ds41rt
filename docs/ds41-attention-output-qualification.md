# dSpark attention output qualification

`DsparkAttentionOutput` now owns inverse RoPE, grouped BF16 output A and native FP8 output B on one stream, borrowing one stage's weights and reusing the output-B owner's input/output buffers. Its graph lifetime covers the cuBLAS handle, fixed workspace, projection scratch and all data buffers; warmup does not publish an output, failures invalidate completion, and destruction drains work and destroys the graph before freeing storage.

The official checkpoint stores `wo_a.weight` as FP8 [8192,4096] with UE8 [256,128] scales, although the reference model executes it as BF16: `convert.py` performs a blockwise dequantization before loading. The coordinator now performs this conversion on GPU for all three stages and retains the converted weights once across waves. Source FP8 tensors remain part of existing auxiliary residency. The initial owner fixture correctly failed the buffer check when handed unconverted checkpoint storage; the final fixture uses the official FP8/scales layout.

The grouped operation maps input [rows,8,4096] and weights [8,1024,4096] to output [rows,8,1024] using a single strided batched cuBLAS GEMM, with interleaved token columns and disjoint group elements. It uses FP32 accumulation, disallows reduced-precision intermediate reductions, and rounds the output to BF16. A dedicated handle and 4 MiB caller-owned workspace support graph replay without transposes or allocation in the launch path.

Both RTX GPUs pass exact dequantization against the hash-checked official conversion formula and numerical grouped products at rows 1, 16, 80, 255, 1023 and 4095 against independent per-group FP32 matmuls rounded to BF16. Projection tolerance is 0.008 relative and 0.002 absolute; changed-input graph replay, exact zero outputs, undersized workspace, invalid rows and overlap checks pass.

The Rust-owned sparse-checkpoint fixture passes all three stages at capacities 1, 16 and 80 on both RTX GPUs. Distinct constant weights per group and stage and varying rows give analytical output values; a second replay changes both input and rotation, cancelling each head's final 64-coordinate sum under inverse ninety-degree rotation. Expected values independently include grouped BF16 rounding, K32 activation quantization and stage output-B scaling. Every output element matches the analytical BF16 result. Stage/budget/row errors, duplicate capture, unpublished warmup and recovery are also checked.

Converted output-A weights add 201,326,592 resident bytes. Each complete output owner needs 4,435,204 bytes at capacity one, 6,889,476 at sixteen, or 17,539,076 at eighty; the existing output-B projection portion is counted once. Three output owners add 44,101,632 bytes per capacity-80 wave beyond the previously admitted projections, raising the partial two-wave total to 8,811,384,920 bytes. Remaining attention/norm/private-KV scratch, shared vocabulary residency, larger prefill owners and driver/graph overhead are still separate.

Native and daemon builds pass. Exact evidence is in `ds41-attention-output-qualification.json`; temporary fixture paths and diagnostic logs are in `TO_DELETE_SCAFFOLDING.md`. QK/softmax/sink computation, frequency ownership, full-stage sequencing, verification and serving integration remain open; no full-model or performance claim is made.

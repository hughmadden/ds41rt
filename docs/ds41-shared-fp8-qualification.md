# Native shared FFN and FP8 projections

The coordinator AOT exporter now builds official K32 FP8 projections for engram [25600,6144], shared gate/up [2304,5120], and shared down [5120,2304], at capacities 1,16,80,256,1024,4096. Matrix C/Rust entry points select both geometry and capacity, with explicit buffer bounds and overlap checks. Existing engram C entry points keep their fixed geometry. The manifest schema is now 2 and records each shape and activation floor.

Native UE8M0 [N/32,K/32] weight scales are replicated into the MMA layout without changing FP8 checkpoint weights. DsparkWeights owns nine packed scale buffers, shared across execution waves, adding 3,317,760 resident bytes. DsparkSharedFfn borrows its exact stage weights and owns projection scratch, gate/up/intermediate buffers and alpha; each capacity-80 stage uses 1,748,996 bytes, or 5,246,988 bytes per three-stage wave. The partial two-wave dSpark budget is now 8,415,327,088 bytes, excluding shared vocabulary-head residency, attention caches/projections and driver/graph overhead.

ExpertExecution::ffn_draft enqueues routing, shared FFN, routed experts and the existing shared-output reduction on one wave stream, draining before returning even after an enqueue error. Stage identity checks reject owners from different resident weights. Shared SwiGLU computes in FP32 with gate clamped only above 10 and up clamped to [-10,10], then rounds to BF16 before the down projection. This is a synchronized Rust composition; combined graph capture and Rust GPU ownership execution remain unqualified.

The zero-input qualification caught a real discrepancy in b12x's default native MXFP8 scale convention. The b12x quantizer now accepts an explicit amax_floor, and the V4.1 exporter uses 1e-4 before power-of-two scale rounding, including for engram. Other callers retain their default convention. The new setting participates in the compilation cache key. Sixteen b12x tests pass for scalar/four-lane/eight-lane paths, K32/K128 groups, zero/tiny inputs, default and explicit floors, graph replay and invalid settings. The dependency fix is committed and pushed as 96066da0ab40d0fcf419d28a69f7895661b44d29.

The rebuilt native library passes scripts/qualify-ds41-shared-fp8.py on both RTX PRO 6000 GPUs: all three geometries at live rows 1,16,80,255,1023,4095 using the corresponding exported capacity; exact FP8 activation values, row scales and packed weight scales; zero/tiny inputs; changed-input graph replay; invalid shape/overlap rejection; and composed shared FFN at rows 1,16,80. Native CUDA and Rust daemon builds pass.

Individual BF16 projections use 0.008 relative/0.002 absolute tolerance against FP32 dequantized reference GEMMs. Composed shared FFN uses the pinned reference's separate K32 accumulation order; activation is bitwise equal for the actual gate/up inputs, including explicit clamp extremes. Small BF16 projection rounding differences can cross the following FP8 quantization boundary, so the composed checks separately bound nonlinear intermediate propagation and the resulting dense projection error rather than requiring bitwise output equivalence. Across these fixtures, final-output maximum absolute error reaches 0.03125 and maximum RMS error 0.000509662; at most four down-input FP8 elements differ in each composed case. These are synthetic numerical checks, not evidence of full-model quality or performance.

Exact library/reference/qualifier hashes and per-case results are in ds41-shared-fp8-qualification.json. Full checkpoint numerical behavior, routed-expert tiny-activation semantics, Rust-owned combined FFN execution, attention/stage orchestration, verification, cancellation and alternating-wave serving remain open. Source inspection found routed-expert phase-1 quantization still calls the default no-floor helper; audit its input/intermediate quantizers next, before treating existing normal-range expert fixtures as sufficient reference coverage.

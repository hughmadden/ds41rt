# Device-resident index page tables

The persistent index owner now exposes stable device buffers for each request's U32 physical page IDs and U64 committed row count. The page-table stride is `min(pool_pages, 4096)`, sufficient for the official maximum of 1,048,576 index rows with 256 rows per page. Only entries below `ceil(committed_rows / 256)` are valid; unused entries remain unspecified. The existing host page list and row count remain available through the same lease-validated borrowed view.

Compressor commit queues accepted index values/scales and pending half-group writes first. It then asynchronously uploads newly appended page IDs and participating request row counts on that wave's stream. Existing page-table prefixes are not recopied. Pinned staging is owned by the cache and remains live until the commit drains. Host page assignments and request versions advance only after this drain. Insufficient page capacity returns before changing either host or device metadata.

Initial device row counts are zero. Request admission resets the slot's device count before returning a live lease. Release/invalidation revoke host leases and clear their device counts; all previous device consumers must already have finished. If a device clear fails, the host lease remains revoked, and admission must successfully reset the count before the slot can be used again. Invalidating several requests attempts every clear and returns the first error. Device-error paths are reviewed, not fault-injected.

The extended real-weight compressor fixture passes 55 cases on each RTX PRO 6000 Blackwell. Its previous 54 cases now compare device page IDs and committed row counts with the host view before/after valid commits, including partial/zero acceptance, changed captured proposals, competing waves, 16 requests, 4096-row prefill and replacement tails. Failed pool reservation preserves both page-table bytes and row counts for all participants. Release and invalidation clear retained device count pointers, while reused slots expose empty histories. Page-boundary reuse checks logical pages in physical order `[1,0]`. An additional case uses 4097 physical pool pages, the maximum 4096-entry table stride and request slot 15, then commits and releases a small history through that view. This verifies metadata addressing at the maximum stride; it does not claim a million-row model execution.

Device metadata costs `slots * (min(pool_pages, 4096) * 4 + 8)` bytes. With 64 pages and 16 slots, this adds 4,224 bytes: total state is now 1,183,872 bytes for ratio two or 1,118,336 for ratio one. Metadata staging costs `pool_pages * 4 + slots * 8` pinned bytes (384 for that configuration). Wave allocations are unchanged. Maximum device metadata is 262,272 bytes per source. Driver/library allocations and other model caches remain separate.

Daemon and external fixture builds pass. Native kernels are unchanged from the index-cache qualification. Adjacent JSON records source, fixture and build/log hashes. The fixture remains in `/tmp/ds41-compressor-owner`; no temporary fixture entry point was added to shipped code.

This completes device page-table publication for the index owner. Sparse scoring/selection must still consume these tables, combine causal proposal rows with committed history and enforce the row-count bounds. Persistent FP8 KV, cross-cache transactions, prefix restoration/sharing, full-model serving and throughput qualification remain open.

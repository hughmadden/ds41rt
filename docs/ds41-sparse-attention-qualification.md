# Direct FP8 sparse attention

The native sparse attention consumer reads K32 E4M3/E8M0 KV directly from four sources: a request's committed 128-row window, its private window proposal, a paged compressed-source pool, and a strided private compressor proposal. It dequantizes only the current 64-key tile into shared BF16 storage. It allocates no global scratch or BF16 cache copy. Query/output geometry is `[rows,64,512]`, with 1–4096 rows per launch. Independent groups of 16 heads use 101,056 bytes of dynamic shared memory per block.

Each query concatenates its oldest-first causal window, padding to the launch's window width, and 512 selected logical source IDs. Window metadata comes from `WindowProposal::metadata`; the following six fields match `IndexProposal::metadata` with slot zero for a narrowed request view. The launch descriptor holds immutable cache/proposal pointers and capacities; metadata, page tables and committed ends reside on the device and can change between graph replays.

Negative, noncausal, unbacked or physically out-of-range source IDs are masked before reading value/scale storage. Invalid proposal bounds, a stale committed end or invalid source stride mask the complete query to zero. Address calculations remain 64-bit through page translation and value/scale access. The Rust wrapper checks buffer sizes, device identity, geometry and paired optional source/selection inputs; the native boundary additionally checks spans, alignment and output overlap.

The numerical path follows the pinned reference's 64-key online softmax: BF16 Q/K with FP32 scores, running FP32 maximum/normalizer, BF16-rounded unnormalized probabilities for the value product, FP32 output accumulation, a learned FP32 sink in the denominator, and final BF16 output. Window padding and selected-ID order determine tile boundaries. This kernel does not apply inverse rotary or output projections.

## Qualification

Both RTX PRO 6000 Blackwell GPUs pass seven numerical cases, each before and after captured replay. They cover 1, 3, 16, 80 and 4096 queries; window-only execution; initial prefill and committed starts 63, 127, 255 and 1023; ratio-one/two source proposals; prior partial compression groups; permuted physical pages; changed query data, proposal offsets, query order, selected order and page tables. Rejected/noncausal IDs and window padding remain masked. Every output coordinate is checked against an independent PyTorch transcription at `rtol=0.008, atol=0.002`. Maximum absolute difference is 0.0078125 on each GPU, in the 4096-query case; general outputs are not claimed byte-exact.

For the first `min(rows,8)` queries in each case, before and after replay, the qualifier also executes the actual pinned TileLang 0.1.8 sparse attention kernel for all 64 heads in four independent 16-head groups. This fits SM120 shared memory and preserves the independent per-head computation. Both the native result and the transcription pass the same tolerance against that reference. This kernel needs no reference compiler arithmetic overrides. Explicit dense copies normalize singleton-dimension tensor strides for the reference FFI.

Device-side malformed metadata checks cover invalid window ends, offsets, counts and positions, plus source slot, end, count, offset and stride. Host-side checks cover null inputs/output, overlapping query/output and unsupported row/window sizes. Output sentinel rows remain intact.

Three additional graph cases allocate the maximum physical source pool: 16,777,216 rows, with 8 GiB of values and 256 MiB of scales, and a 4096-entry page table. An analytic uniform-query case reads a selected row near the physical pool end, beyond 4 GiB, then replays with a different valid page and an out-of-range page. Every output coordinate matches the expected BF16 value exactly, including the sink contribution and private source/window rows. Only explicitly initialized selected rows are read; this does not scan the whole large pool.

The external Rust fixture checks a valid window-only captured launch and changed-value replay against an exact analytic result, plus undersized/null/wrong-device buffers, output overlap, invalid geometry and an unpaired selection. Native library, daemon and fixture builds pass. Adjacent JSON records source, build, fixture and qualification hashes. Reusable Python qualification is tracked; the small Rust driver remains outside Git.

This qualifies the fixed FP8 serving policy. Reference compressed KV uses FP4 group16/E4M3, as documented in `ds41-kv-qualification.md`; no equivalence to that compressed encoding is claimed. The caller must still bind queries, selected IDs, window/source request leases and exact proposal snapshots, enforce causal source counts, and keep inputs immutable through completion/replay. Owned composition with selection, attention query/output production, backbone execution, scheduler integration, dSpark FP8 storage and full-model correctness/performance remain open.

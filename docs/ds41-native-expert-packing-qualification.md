# Native V4.1 expert weight preparation

The C/CUDA packer and preloaded Rust `V41ExpertPacker` convert one official checkpoint expert at a time into the b12x N256/K128 representation. Inputs are separate native W1/W3/W2 FP4 bytes and their K32 E8M0 scale grids; output buffers contain packed W13/scales and W2/scales. The up half (W3) precedes the gate half (W1), with each half padded independently. The transform preserves payload bits and performs no quantization. Logical intermediate sizes are restricted to RTX dSpark 2304 and backbone TP4 576, with Spark execution padding to 640.

Source buffers remain unchanged and may be reused after stream completion. Destination buffers are caller-owned, 16-byte aligned and disjoint from each other and every source. The entry point validates geometry, null pointers, alignment and overlap, launches without allocation or synchronization, and writes all packed bytes including zero padding. Buffer capacity, device residency and ordering remain unsafe caller obligations.

Byte-for-byte comparisons against b12x's independent reshape/permute representation passed for both widths on both local RTX GPUs and ostrich GB10, including changed-input graph replay without allocation, preserved source bytes, trailing output guards, zero padding and invalid geometry/overlap/alignment rejection. M16 expert numerical and changed-input graph checks also passed through production Rust weight packing, native scratch initialization/binding, native AOT expert execution and Rust/CUDA reduction on RTX 0 and ostrich. The existing relative-L2 < 0.01 and cosine > 0.9999 gates were retained. The Spark fixture checks a local shard using three zero reducer planes, not network TP execution. Both architecture builds and daemon compilation pass (427 existing daemon warnings).

The packed backbone weights require 80,216,064,000 bytes per Spark across 40 layers and 384 experts, versus 72,194,457,600 native checkpoint bytes: 8,021,606,400 extra bytes from intermediate padding. Per-expert logical staging requires 4,700,160 bytes for a Spark shard or 18,800,640 bytes for dSpark, and can be reused sequentially rather than retaining a full logical layer beside packed storage. Caches, route planes, scratch and all other allocations are additional. The packer exposes the four per-expert output byte strides for caller budgeting.

Python still allocates and constructs synthetic fixture tensors and supplies the outer binding carriers. Checkpoint reads into bounded staging, production GPU allocation/weight-binding ownership, per-route transport and scheduler/model execution remain open. These results do not qualify full containers, serving scripts, native vision/dSpark model execution or checkpoint bring-up. Exact hashes and results are in `ds41-native-expert-packing-qualification.json`.

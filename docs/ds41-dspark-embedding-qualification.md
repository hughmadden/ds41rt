# dSpark embedding inside the three-stage graph

`DsparkWeights::embedded_chain` borrows the coordinator's existing `embed.weight` owner. The graph starts by selecting each request's seed token followed by four copies of noise token 128799, repeating every BF16 embedding across four hyperconnection streams and initializing pre-mix to `[1,0,0,0]`. This follows `DSpark.forward_embed` and the initial mix in the pinned official reference, revision `df42c109f1defefcbfcedbe7d905718a12266e40`.

The shared 1,323,827,200-byte table remains owned once by the coordinator. Each chain adds four device bytes per request for seed IDs, with no embedding workspace or additional table. Chain allocations are 62,157,520, 64,154,568 and 228,906,532 bytes at 1, 3 and 16 requests. The partial two-wave dSpark plan is now 8,853,577,712 bytes; shared embedding/vocabulary tables and other coordinator allocations are separate. This is not a final RTX memory-fit claim.

`set_tokens` validates count and vocabulary bounds before upload and clears output and token readiness on failure. Seeds must follow the current cache-binding row order. The graph retains the table's lifetime and reads the stable seed buffer on every replay. Cache binding counts must equal the supplied seed count. The native kernel also checks IDs before indexing and zeroes the entire request's output for an invalid device ID; pointer overlap, alignment and request-count guards run before launch.

Both RTX PRO 6000 GPUs passed nine native cases each: 1, 3 and 16 requests, changed seeds under graph replay, and invalid device IDs. Outputs match a PyTorch embedding/repeat oracle exactly, including first/last vocabulary IDs, noise-token seeds and column-dependent values. Count, overlap and alignment guards reject invalid calls.

Both GPUs also passed six composed-chain cases each using synthetic sparse checkpoint payloads and the production tensor loader. Seed IDs change between capture and replay, packed request order reverses and committed positions advance. Graph outputs match three separately synchronized stages initialized from host-generated embeddings bitwise, for both residual and pre-mix. All three committed rings remain unchanged. Invalid, empty, excessive and mismatched seed counts reject execution without publishing stale output; valid inputs recover. Existing cache-owner and lease guards remain covered.

Native CMake and daemon builds passed. Source, fixture and result hashes are in the adjacent JSON. The fixtures remain outside Git under `/tmp/ds41-embed` and reuse `/tmp/ds41-stage` sparse weights. These tests qualify embedding semantics and graph composition with synthetic weights, not real-checkpoint logits or generation. Terminal vocabulary/Markov/confidence/sampling integration, target verification and backbone/vision/serving wiring remain open.

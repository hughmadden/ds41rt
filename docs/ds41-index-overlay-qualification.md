# Causal index proposal overlays

Index selection must see completed latents from the current forward pass before acceptance is known. The scorer now combines immutable committed pages with an append-only view into the compressor wave's packed index proposals. It never publishes proposals to the persistent cache. This is the index-key FP4/E8M0 representation; persistent serving KV remains an FP8-only requirement.

`ds41rt_v41_index_scores_overlay` takes six U64 fields per query: request slot, causal compressed-row count, committed append start, proposal count, physical proposal offset and proposal step. Step 1 addresses ratio-one source rows; step 2 skips incomplete ratio-two rows. The first completed row can be either the first or second wave row, depending on whether a pending half-group existed at entry. No compaction copy or allocation is needed.

Candidates below the committed length use the request's page table. Later candidates use `offset + (position - committed) * step` within the immutable proposal buffer, and may lie beyond the currently allocated committed page table. Both paths enforce the query's causal length. The append start must equal the device-published committed length. Invalid start/count/offset/step descriptors suppress the entire query, and bounds use subtraction to avoid U64 wraparound. Invalid slots, logical candidates and physical pages are masked before key/query reads. The operator retains BF16 rounding at dot product, weighted product and head sum. Its existing committed-only entry point uses the same templated numerical body.

`CompressorWave::index_proposal` validates all wave leases, generations, versions and committed token positions through the existing ready-output checks, then exposes one request's borrowed cache and proposal view. The borrow ties consumers to both the wave and state. `IndexProposal::metadata` accepts only query token positions inside that request's current chunk and derives the causal compressed length `(position + 1) / ratio`. Its page-table view has one slot, so metadata uses slot zero. Consumers must drain work before releasing the borrows; raw FFI callers remain responsible for owner/version validation and serialization. The metadata checks do not independently authenticate another wave that happens to have the same append start.

## Qualification

The reusable `scripts/qualify-ds41-index-overlay.py` passes eight cases on each RTX PRO 6000 Blackwell GPU. It extracts the pinned official reference's two BF16 scoring assignments and compares every score exactly. Shapes cover 1–4096 queries, 3–16384 candidates, 16 request slots, stride 4096 and a 16,777,216-row physical pool. Both proposal strides, page-boundary appends and wholly uncommitted prefill are included. Captured replay changes queries, head weights, committed keys, proposal keys, page mappings, proposal counts and offsets. Stale append starts, changed published lengths, invalid descriptor fields and zero causal lengths produce only negative infinity. Native pointer, output overlap and shape guards are exercised.

The real-weight compressor fixture passes its existing 55 cases per GPU, plus **425 request-proposal checks per GPU**. Before each accepted-prefix transaction it borrows the proposed view, captures overlay scoring plus top-512 selection, and replays at the request's last, first and middle query positions. Synthetic unit query/head inputs isolate addressing and causal visibility; keys are the actual real-weight compressor outputs. CPU decoding of the exact packed keys provides the score oracle, followed by deterministic score/lowest-ID top-512 selection. Queries see only completed groups. Invalid query positions are rejected. A stale append descriptor yields all-negative-infinity scores and all-minus-one selections. Both committed cache bytes and source proposal bytes remain unchanged. The view is rejected after consuming its wave, and competing views are rejected after another wave advances the state version, including zero acceptance.

These owner cases retain ratio-one/two partial-group checks, 16-request batches, changed request ordering, 4096-token bulk prefill, rejected-tail replacement, pool exhaustion, physical page reuse and maximum page-table stride. Separate committed-history scoring regression passes all seven prior cases on each GPU after templating the kernel. Native library, daemon and external owner fixture builds pass. The adjacent JSON records source/build/fixture hashes and results; temporary owner drivers remain outside Git in `/tmp/ds41-compressor-owner`.

Learned-query/selection composition, request-owned candidate sharing, sparse attention, persistent FP8 serving KV, scheduler integration, full-model correctness and throughput remain open. No full-model readiness or performance claim follows from these component checks.

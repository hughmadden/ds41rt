# Target token initialization and initial block handoff

`v41_target_embedding.rs` borrows the coordinator's existing `embed.weight` owner, which dSpark also borrows. It allocates no second copy of the 1,323,827,200-byte BF16 table. Each text token expands into four identical 5,120-coordinate residual streams and an FP32 `[1,0,0,0]` incoming pre-mix, matching `Transformer.forward` and `make_identity_pre_mix` in the hash-locked reference.

The native gather/expand kernel is shared through separate target and dSpark template instantiations. The target accepts 1–4,096 token rows; dSpark retains its seed plus four noise-token rows per request. Invalid device IDs zero the affected output, while the target owner rejects invalid host IDs before upload. Source/output overlap and invalid geometry are rejected at the FFI/native boundaries.

Each target wave owns its token buffer, residual/pre buffers, stream and graph. Its budget is 40,980 bytes per capacity row: 40,980 at 1, 655,680 at 16, 3,278,400 at 80, 10,490,880 at 256, 41,963,520 at 1,024 and 167,854,080 at 4,096. Budget admission precedes allocation. Live shapes are captured on first use and recaptured when their row count changes; readiness-time shape preparation remains an integration requirement. Published output borrows the owner and retains token IDs and positions in caller order. Failed calls and graph clearing unpublish output, and queued work drains before publication or storage release.

`BackboneBlockWave::initialize_embedding` validates layer 0, capacity, row extents and device before supplying the first block's residual/pre inputs. It leaves block output unpublished. `begin_embedded_attention` adds a layer-0 query check and invokes the existing attention entry using the embedding's positions. Text embedding initialization does not implement image replacement; the reference merges image embeddings before expanding the residual streams, which still requires the vision path.

On ostrich's GB10, two changed input sets at capacities 1, 16, 80, 256, 1,024 and 4,096 passed owner tests with two independent waves, exact output agreement, shape recapture, budget limits, invalid IDs/positions/counts, unpublished output and recovery. Tests include IDs 0, 128799 and 129279, repeated IDs, repeated positions and position 1048575. Native invalid-ID zeroing and overlap/row guards passed. An 80-row copy into real layer-0 block storage was byte-exact; a layer-1 block and a one-row block rejected it.

`scripts/qualify-ds41-target-embedding.py` independently reads the official safetensors embedding payload on CPU and executes the hash-locked `ParallelEmbedding.forward` and `make_identity_pre_mix`. All 12 target sets and two dSpark sets (1 and 16 requests) matched every residual and pre-mix byte exactly. The final fixture's regenerated payload hashes match this numerical run. This covers the changed shared gather kernel's dSpark embedding behavior, not complete draft graphs.

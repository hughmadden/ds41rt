# Owned CSA2 compressor execution and partial-group state

`CompressorWeights` loads only an official source layer's native BF16 compressor tensors, shared across wave owners. `CompressorState` owns up to sixteen request slots and the pending FP32 KV/gate pair for ratio two. Ratio one needs no device state. `CompressorWave` owns input, projections, descriptors, normalized unrotated output, a cuBLAS workspace, pinned descriptor staging and a captured graph.

Requests begin at position zero with unique owner/generation leases. Admission rejects occupied slots and duplicate logical request IDs. Packed chunks must contain distinct live leases, positive token counts, exactly matching committed positions and a total of at most the wave's fixed row capacity. Position arithmetic is checked before enqueue. Descriptors select a committed pending half-group only when the request's committed end is odd; new or reused slots cannot read stale pending allocations. Completed-row metadata identifies the output row, request lease and first represented token position for later RoPE/index/cache work.

Proposal execution and graph warmup leave committed state unchanged. Capture freezes the state owner and live row count; replay may change request order, per-request chunk lengths, positions and predecessors while retaining those bindings. Outputs borrow both the wave and state and validate request versions before publication. Every commit consumes its proposal once and validates all requests and acceptance counts before any device write. Only an accepted prefix ending in a half-group copies its last accepted KV/score projection into pending state. Rejected suffixes are never copied. The returned latent list contains only accepted complete groups.

Each committed request advances a proposal version even when it accepts zero tokens, rejecting competing stale-wave outputs and commits at an otherwise unchanged position. Invalid commit input clears the proposal without changing request state. Submitted commit copies are drained before metadata advances; a copy or synchronization error invalidates all participating requests. The latter device-fault branch was reviewed but not exercised by GPU fault injection. Explicit invalidation supports failures in a later containing cache transaction; a transaction spanning all model caches is not implemented here.

The production Rust owner and loader passed on both RTX PRO 6000 GPUs using the real compressor weights at layers 2/8/14/20. Each GPU ran 48 proposal cases: four sources, 1/3/16 requests and four attempts with changing activations, zero/partial/full acceptance, reversed packed request order and changed chunk lengths at the same captured row count. The reference generator reconstructs each request's history using accepted tokens only, so later outputs detect contamination from rejected proposals. Completed and accepted latent addresses match exactly. Numerical outputs pass the previously established BF16 tolerance `.004 + .016 * abs(reference)`; maximum observed absolute error is `.0078125`. Replays with unchanged state and inputs are byte-identical.

Guards cover weight/state/wave budget admission, invalid source/row/slot capacities, duplicate requests and chunks, unpublished warmup, duplicate capture, foreign capture owners, stale positions, empty/oversized batches, excessive acceptance, duplicate commit, competing stale proposals, released leases and physical slot reuse. Zero-input slot-reuse checks compare numerical zero, allowing signed BF16 zero from negative normalization weights.

Two additional cases per GPU fill the maximum 4096 input rows with sixteen 256-token requests, for ratio two (layer 2) and ratio one (layer 20). Requests accept different prefix lengths, then submit replacement tail tokens in reversed order. The tail reference includes only those accepted prefixes. Prefill/tail maximum absolute errors are `.0078125/.0009765625` for layer 2 and `.00390625/.00390625` for layer 20. Replay rejects the changed live-row count, while ordinary execution handles the smaller tail batch correctly.

A ratio-two wave uses 5,423,744 device bytes at 80 rows or 67,141,632 at 4096; its shared sixteen-slot state uses 65,536 bytes. Ratio one uses 5,177,344 or 54,525,952 wave bytes and zero state bytes. Native source weights add 10,486,784 bytes for each ratio-two source or 5,243,904 for ratio one, once per source rather than per wave. Driver/library/graph allocations and downstream caches are separate. Pinned descriptors are bounded at eight bytes per row and exist only for ratio two.

The daemon and fixture builds pass. Adjacent JSON records source, generator, fixture, vector-inventory and log hashes. Temporary fixtures are under `/tmp/ds41-compressor-owner`; they are not shipped source. Native kernels are unchanged from the prior real-weight compressor qualification. Index-key generation, compressed-cache rotation/quantization, shared source/reindex/reuse ownership, hierarchical selection, sparse attention, cross-cache transactions, prefix restoration and production scheduling/overlap remain open. This does not establish complete model execution or throughput.

# Native TP4 across four physical Sparks

Two changed-input M16 requests passed through four physical GB10 workers, with rank 0 on ostrich, rank 1 on dodo, rank 2 on emu and rank 3 on kiwi. Each worker loaded synthetic official-shaped layer-0 expert weights with current production Rust ownership/execution code and a freshly built SM121 native library. All workers used byte-identical executables, native libraries and sparse checkpoint archives. The exporter validated SparkInfer revision `02fea5c504f75f80fe3ec5e4e22ff20338e66803`, SM121 and 48 physical SMs.

The RTX client sent identical revision-3 requests to all ranks over persistent TCP connections, consumed responses in rank order 3/1/0/2, validated identities and ordered six FP32 route planes per token, then performed TP4 reduction and shared-output addition on RTX. Both resulting 163,840-byte BF16 outputs matched the independent full-width-2304 expert reference bit-for-bit. A fresh reference regeneration against the current source and synthetic checkpoint reproduced every input and expected output exactly. The cases change hidden values, expert ordering and shared output; selected experts carry nonzero synthetic data rather than full checkpoint values.

The temporary harness copies current `v41_experts.rs`, `v41_experts/execution.rs` and `v41_memory.rs`; only unused dSpark/service/coordinator module declarations are omitted from the owner module to build the standalone fixture. Method bodies are unchanged. This qualifies native layer ownership/execution, complete-plane wire validation and real four-host arithmetic; it does not qualify the production listener/bootstrap, coordinator scheduler, indexed streaming chunks, RDMA, graph overlap, full model output or performance.

Fresh ARM and coordinator fixture builds passed. Ostrich ran the Spark development image; dodo, emu and kiwi ran already installed compatible runtime images with the freshly built native library and fixture mounted into isolated containers. Dodo lacked the development-image tag, so its initial launch attempt failed before creating a worker and the available runtime image was used. This is not a release-container deployment check. Exact image IDs, source/fixture/artifact hashes, endpoints and logs are recorded in `ds41-four-spark-tp4-qualification.json`.

All workers printed READY and DONE and exited with status zero after the two requests. The four named qualification containers were removed, and ports 41870–41873 were verified clear on their respective hosts. Serving deployment was not changed. Temporary source archives, sparse checkpoints, binaries and output evidence remain under `/tmp/ds41-tp4-four-host/` for handoff and are listed for Goal 2 cleanup.

# Native V4.1 mHC boundaries

`ds41rt_v41_hc_pre` collapses four BF16 residual streams using the incoming FP32 pre-mix, with FP32 products/sums and one final BF16 round-to-nearest conversion. `ds41rt_v41_hc_post` expands a BF16 sublayer result with FP32 post coefficients and adds the mixed residual, also rounding only the final result. Combination coefficients use `[source,destination]`, matching the official reference's sum over the source axis. Products and sums explicitly avoid fused multiply-add to preserve reference intermediate FP32 rounding. Kernels use wide offsets, reject invalid geometry and output/input overlaps, and allocate no workspace.

The library-borrowing Rust handle validates buffer sizes. dSpark terminal execution now owns residual `[5,R,4,5120]` and incoming pre-mix `[5,R,4]` buffers and enqueues collapse before final normalization, shared-head projection, Markov sampling and confidence. Its inputs are residual, pre-mix and anchor IDs; upstream stage execution must supply the shifted pre-mix, rather than recomputing coefficients from the final hidden state. The collapsed state remains the confidence input, while vocabulary projection uses its normalized version.

Synthetic signed/asymmetric pre/post/combination coefficients passed bitwise comparison to the pinned reference operations on both RTX GPUs at 1, 16 and 80 rows, including changed-input graph replay and output-alias rejection. The existing vocabulary/Markov/confidence and five-step sampling graph checks also passed against the updated native library. These checks do not qualify coefficient generation/Sinkhorn, complete layer execution, the Rust terminal owner or full serving.

The additional residual/pre-mix buffers require 3,278,080 bytes at 16 requests. Terminal storage is now 104,368,448 bytes, and two capacity-80 expert/terminal waves plus resident dSpark tensors require 8,293,027,672 bytes before the shared head and other excluded coordinator/cache allocations. The native library and Rust daemon builds passed; exact hashes and numerical evidence are in `ds41-hc-qualification.json`.

The native mHC coefficient producer now fuses the 24-output FP32 projection of the flattened BF16 residual, its RMS scaling, sigmoid pre/post coefficients and twenty Sinkhorn iterations. It uses the official 1e-6 normalization and coefficient epsilons. The combination matrix begins with row softmax plus epsilon, then column normalization; the remaining nineteen iterations alternate row and column normalization. Coefficients stay FP32, and no projection intermediate or kernel workspace is allocated. This implementation has numerical evidence but no throughput claim.

`DsparkWeights::hc_sublayer` creates an owned boundary for either attention or FFN in any of the three dSpark stages. `begin` computes new coefficients from the current residual, collapses using the incoming pre-mix and normalizes the sublayer input. After attention/FFN writes its result, `finish` applies the generated post/combination coefficients and exposes the expanded residual plus new pre-mix for the following sublayer. The initial pre-mix is one-hot `[1,0,0,0]`; the generated pre-mix is never substituted for the incoming one. Completion checks prevent finishing before begin or exposing incomplete outputs. The current owner synchronizes each boundary; graph orchestration around the intervening attention/FFN remains to be implemented.

The expanded synthetic qualifier validates hashes for both official model and kernel references. Fused coefficient values passed at 1, 16 and 80 rows, changed-input graph replay and zero-residual/saturated-bias cases on both RTX GPUs, with maximum absolute error 7.153e-7 under fixed 2e-5 absolute/relative tolerances. Overlapping coefficient outputs were rejected. Existing bitwise mHC boundary tests and dSpark head/sampling checks also passed. This does not qualify full sublayer execution, Rust resource lifetimes, overlap, performance or serving.

Each capacity-80 sublayer owner uses 9,020,160 bytes. Planning six independent attention/FFN owners per dSpark wave adds 54,120,960 bytes; two complete partial waves plus resident dSpark tensors now require 8,401,269,592 bytes, excluding the shared vocabulary weight, attention caches, stage projection workspaces and library/driver/graph allocations. The daemon and native builds passed. Evidence and exact source hashes are in `ds41-hc-mixes-qualification.json`.

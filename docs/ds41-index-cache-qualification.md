# Request-owned persistent index cache

Each CSA2 compressor state now owns one bounded physical index pool, shared by its request slots. Pages contain 256 compressed index rows, stored as separate 64-byte FP4 values and four-byte E8M0 scales per row. Callers supply the pool page count and device budget explicitly; the pool supports 1–65,536 pages. Requests acquire pages as accepted history grows, preserving existing physical page assignments. Release and invalidation return pages for reuse. A source's downstream index consumers can borrow its cache view rather than allocate duplicate keys.

`CompressorState::index_cache` validates the owner/generation lease and returns physical buffers, a borrowed logical-to-physical page list and the initialized row count `committed_end / compress_ratio`. Newly admitted or reused slots expose zero rows and no pages. Device consumers must finish before release or state mutation; raw device views are not independently owned snapshots. Page padding and free pages are not initialized for attention reads.

Commit consumes the proposal and validates every request's version, position and acceptance count, then reserves every required page without changing the pool. Insufficient capacity returns before any pending-state or index write. Accepted complete groups generate unique physical row destinations; incomplete and rejected proposal rows retain the skip sentinel. A pinned descriptor upload, native scatter and pending half-group copies run on the wave's stream. Commit drains them before applying page assignments and advancing request positions/versions. Zero acceptance advances the version without allocating pages or writing index rows. A submitted copy/kernel/drain failure invalidates participating requests after the drain attempt, preserving the existing compressor failure policy; device-fault recovery was reviewed, not fault-injected. The transaction spanning KV, index and other model state remains to be implemented.

The native scatter uses 64-bit row addressing and checks input/output spans for null pointers, descriptor alignment, overflow and overlap. Each valid descriptor writes one 64-byte value row and four scale bytes; a descriptor at or above capacity is skipped. Caller validation supplies uniqueness and request ownership.

`scripts/qualify-ds41-index-store.py` passes five cases on each RTX PRO 6000 Blackwell: row/capacity pairs 1/1, 3/257, 80/1024, 4096/8192 and 4096/16777216. Whole-cache comparisons verify only selected rows changed, including the highest physical row, reverse ordering, sentinel/out-of-range skips, changed-data/destination graph replay and all-skipped replay. The largest case checks 1,140,850,688 cache bytes. Invalid shapes, null/overflow pointers, descriptor misalignment and overlapping spans are rejected. The mathematical oracle here is exact byte copying, not a numerical tolerance.

The real-weight compressor fixture passes 54 cases per GPU: its previous 50 projection/pooling/index/acceptance cases plus one page-pool case for each source layer 2/8/14/20. Valid commits now compare the entire physical values/scales pool against prior contents with only accepted complete rows overwritten. This covers 1/3/16 requests, two competing graphs, changed request order, partial/zero acceptance, 4096-row prefill and replacement tails. Pool-specific cases fill both available pages, verify failed reservation leaves bytes and positions unchanged, permit zero acceptance while full, reclaim a released request's page, append across the page boundary in physical order `[1,0]`, reject stale leases, expose empty histories on slot reuse, and recover capacity through explicit invalidation. Upstream numerical qualification retains its previous reference tolerances.

A pool page costs 17,408 device bytes. With 64 pages and 16 request slots, state uses 1,179,648 bytes for ratio two or 1,114,112 for ratio one. A wave adds eight device bytes per proposal row for commit destinations and reuses its existing pinned metadata staging after proposal execution drains. Ratio-two waves use 5,491,904 bytes at 80 rows and 70,631,424 at 4096; ratio-one waves use 5,245,504 and 58,015,744. Shared weights, driver/library/graph allocations and other model caches are separate. Host page lists are bounded by the configured pool capacity.

Native library, daemon and fixture builds pass. Adjacent JSON records source/build/log hashes and primitive results. The reusable scatter qualifier is tracked; the extended owner fixture remains under `/tmp/ds41-compressor-owner` and is not shipped code. It uses the real checkpoint tensors and prior reference vectors identified in the compressor/index qualification records.

Persistent index writes are complete within this component. GPU page-table handoff to selection, proposal-overlay attention, prefix-cache sharing/restoration, persistent FP8 KV storage, shared source/reindex/reuse execution, cross-cache commit, full-model serving and throughput qualification remain open.

# Native RTX dSpark residency

`v41_experts::dspark::DsparkWeights` owns all three independent 128-expert stage sets and every remaining `mtp.*` tensor on the current coordinator RTX. Native FP4 experts use the existing packer; auxiliary tensors keep their official FP8, E8M0, BF16 or FP32 representation through bounded pinned staging. The backbone embedding and output head are shared by the reference and must be borrowed from coordinator residency rather than duplicated here.

Planning validates all stage placements and admits resident weights plus expert execution buffers for one or two waves before payload reads. Experts load serially before auxiliary tensors, so loading peak is packed expert residency plus one expert staging allocation. Each execution wave owns three independent stage workspaces, allowing distinct captured graphs without rebinding their weight addresses; the Rust borrow prevents weights from dropping before their executions. Callers account for every live wave using its selected capacity.

Static accounting from the official tensor template and current coordinator AOT manifest gives 7,219,445,760 bytes of packed experts and 713,428,872 bytes of auxiliary tensors. Capacity 80 covers sixteen requests with five draft positions each; its expert execution storage is 25,236,024 bytes per stage and 75,708,072 bytes per three-stage wave. Two such waves plus resident tensors require 8,084,290,776 bytes before attention caches, dense projection scratch/packed scales, shared backbone embedding/head, and CUDA graph/driver allocations. This is a partial allocation budget, not measured total GPU usage.

The daemon build passed with 447 warnings. No model load, GPU tests or placement benchmarks were run. Attention execution/cache ownership, native dense projection integration, Markov/confidence execution, sampling/verification, rollback and serving scheduler call sites remain unfinished; this owner does not yet execute a complete dSpark stage. Build evidence is in `ds41-dspark-residency-build.json`.

# Engine-owned V4.1 expert layers

The daemon's `v41_experts` module now owns native packed expert storage. `ExpertWeights::plan` reports resident bytes, device staging, pinned host staging and CPU read scratch before allocation. `load` enforces the native RTX/dSpark or Spark/backbone role, rejects insufficient device budgets, reads every expert through the validated catalog, and uses native packing into four resident buffers. It retains no logical layer copy.

Loading uses one reusable pinned host buffer, one device staging buffer and a dedicated stream. Each expert's transfer and packing complete before those buffers are reused. The stream guard is declared after the buffers so failure cleanup drains pending work before freeing storage. Allocation owners borrow the native library and release buffers on normal or error exits. Prepared weight binding fills the AOT pointer carriers after scratch binding, using the native unit global scales for the weight alphas. Captured graphs must not outlive the weight owner; graph and scheduling ownership are not yet implemented here.

Complete synthetic layer loads passed on RTX 0 (128 dSpark experts, 2,406,481,920 resident bytes) and ostrich (384 backbone experts for TP rank 3, 2,005,401,600 resident bytes). The dSpark load uses 18,800,640 bytes each of pinned and device staging; the Spark load uses 4,700,160 bytes each plus 73,728 bytes of CPU read scratch. CUDA modules, execution scratch, route planes, caches and other model allocations are outside this component budget.

The first, middle and last experts' four bound packed buffers match an independent physical checkpoint selection plus b12x reshape/permute reference exactly on both architectures. A temporary CUDA allocation interposer verifies that budget rejection performs no allocations, failed device/pinned allocations and checkpoint I/O release all tracked allocations, successful loading retains exactly four device buffers and no pinned staging, and dropping the owner returns both device and pinned allocation counts/bytes to baseline. Injected failures occur after two successful device allocations and after all five device allocations before pinned staging allocation. The initial RTX machine-wide free-memory check passed, while ostrich's free-memory counter increased during the check; process-specific tracking replaced that unsuitable exact counter assertion. The interposer's initial symbol lookup also required correction for the locally loaded CUDA runtime; production loader code was unchanged by these fixture fixes.

The temporary executable compiles the production daemon module directly and loads the complete validated sparse-header fixture with selected nonzero synthetic expert payloads. This is not downloaded-checkpoint integrity or model output qualification. Daemon compilation passes with 438 warnings, including unused entry points awaiting serving integration. Native binding addresses and loaded storage are checked here; executing graphs with this engine owner, integrating coordinator/expert services, per-route transport, full model execution and complete build/run qualification remain open. Exact source and fixture hashes are in `ds41-owned-expert-qualification.json`.

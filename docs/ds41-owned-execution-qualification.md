# Owned native expert execution

The daemon now provides one `ExpertExecution` owner per independent execution wave. It borrows resident expert weights and owns a stream, scratch, hidden states, I32 routing IDs, FP32 routing weights and an optional captured graph. RTX dSpark instances additionally own BF16 shared-expert and final-output buffers; Spark instances expose bounded FP32 route-partial views for later transport. Buffer budgets are available before allocation and exclude CUDA module/graph metadata and other model state.

Construction binds native scratch and resident weights, initializes scratch, and completes initialization before use. Direct launch consumes caller-produced valid inputs on the owner's stream. Capture warms the exact launch, ends capture on success or failure, and retains one fixed row/shared-output shape. Replays can consume changed input values. Destruction drains the stream and destroys its graph before buffer owners release storage. Rust lifetimes keep resident weights and the native library alive while the execution owner exists; external producers and readers remain responsible for valid routing, device placement and stream ordering.

The qualification executable compiles byte-identical copies of the production daemon modules and loads complete synthetic checkpoint-shaped expert layers. On RTX 0 and ostrich it creates two independent 16-row instances, runs direct batches of 1/7/15/16 rows, captures both M16 instances, changes hidden states, expert order and shared values, and replays the two instances in alternating order four times. Outputs meet the independent K32 FP8/BF16 expert oracle's relative-L2 < 0.01 and cosine > 0.9999 gates. Swapped-input replay results equal the corresponding direct results bit-for-bit. Only M16 graph shapes were captured; smaller row counts were checked by direct launch.

The RTX graph includes native routed-expert reduction and shared-output addition. Spark graphs emit local FP32 route planes; the fixture reduces each local result with three zero TP planes and adds externally supplied shared output afterward, so this does not qualify distributed TP execution. Per-process CUDA allocation tracking detects no new device or pinned allocations during replay, confirms execution-budget rejection before allocation, and confirms device allocations return to the resident-weight baseline after execution teardown. Checks also reject invalid row counts, replay before capture, duplicate capture and Spark-local shared-output launch.

Per-instance buffer budgets are 7,793,544 bytes for the RTX M16 variant and 12,046,356 bytes for the Spark M16 variant, including all owned inputs and output buffers but excluding resident weights. Daemon compilation passes with 444 warnings, including currently unused entry points pending serving integration. No performance or admission/concurrency claims follow from these component checks. Scheduler admission, request-state ownership, transport/RDMA, full model layers, native vision/dSpark model execution and complete build/run qualification remain open. Exact hashes, run logs and numerical results are in `ds41-owned-execution-qualification.json`.

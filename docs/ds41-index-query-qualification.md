# Learned index query production

The RTX query producer loads the official `indexer.wq_b` FP8 weight/E8M0 scale and BF16 `weights_proj` weight for layers 2, 8, 14, 20, 24, 28, 32 and 36. Other layers are rejected by this producer; their selection reuse remains a separate integration task. The input is already-normalized BF16 query rank `[rows,1280]`, attention-input hidden states `[rows,5120]` and matching token positions. The producer does not normalize query rank a second time.

The graph runs native backbone frequencies, K32 FP8 projection to `[rows,32,128]`, BF16 head projection to `[rows,32]`, then fused rotary/FP4 preparation. Rotary applies to the final 64 query coordinates and rounds back to BF16 before packing. Queries use the reference FP4/E8M0 index encoding, with groups of 32. Head weights receive the reference `128^-0.5 * 32^-0.5 = 1/64` factor and BF16 rounding. This index encoding is distinct from the fixed FP8 serving KV cache contract.

`IndexQueryWeights` shares 5,739,520 device bytes per producing layer, including 163,840 bytes of packed MMA scales. Admission precedes tensor payload reads. Each `IndexQueryWave` owns its stream, cuBLAS handle/workspace, FP8 scratch, input/output buffers and graph. Wave allocation is `4 MiB + FP8 scratch + 4 + capacity * 23560` bytes: 4,226,060 at capacity 1, 6,190,724 at 80 and 106,266,628 at 4096. Two alternating waves borrow the same immutable weights. Graph capture freezes live row count; rejected execution/replay/capture calls unpublish prior output. Output views expose only live rows and borrow their wave. Callers must provide matching initialized inputs, valid positions and completed producer writes, and bind results to the correct request snapshot.

## Numerical evidence

`scripts/qualify-ds41-index-query.py` reads actual checkpoint tensors and pins the official model/kernel/config hashes. All eight layers and six capacities (1, 16, 80, 256, 1024, 4096) pass on both RTX PRO 6000 Blackwell GPUs. Larger capacities use 255, 1023 and 4095 live rows to exercise tails. Each case checks initial execution, captured execution after changing inputs/positions, and zero-input replay.

FP8 query and BF16 head projections agree with the official FP8 GEMM and PyTorch BF16 linear within `rtol=0.008, atol=0.002`. Native activation FP8 and E8M0 bytes match the official quantizer exactly. Frequencies match the official YaRN table exactly. Fused query packing matches official rotary plus FP4 quantization applied to the **native BF16 projection output**, byte for byte; scaled head weights are exact relative to their native BF16 projection. This does not claim bitwise equality between differently ordered GEMM accumulations or their downstream quantization at rounding boundaries. Zero checks preserve signed FP4 zero from rotary arithmetic. Native null/overlap/row guards are checked.

The reference environment uses TileLang 0.1.8 and TVM FFI 0.1.6. FFI 0.1.2 failed FP8 GEMM compilation with a non-Boolean allocation condition. With 0.1.6, the default vectorized reference activation quantizer produced non-finite values in reference-only runs at 2048/4095/4096 rows. Inspection found shared BF16 input/FP8 output storage aliasing without an intervening cross-warp barrier, consistent with that failure. The qualifier explicitly sets `tir.disable_vectorize=True` **only for the reference activation quantizer**, leaving its source and numerical arithmetic unchanged. Full-size calls then pass; the qualifier does not chunk the oracle or lower the native live row count. TVM FFI is explicitly bound to the Torch stream. The adjacent JSON records this compiler override.

The 48 numerical cases also pass inside the coordinator development container on GPU 0. Host qualification uses Torch 2.13/CUDA 13.0; the container uses Torch 2.12 development/CUDA 13.2. Their cuBLAS head outputs can differ at BF16 rounding boundaries. Container-generated, reference-checked vectors are therefore used for exact container ownership comparisons, rather than demanding identical cuBLAS bytes across versions.

## Ownership and regression evidence

The external Rust fixture `/tmp/ds41-index-query-owner` passes 48 cases on each GPU in the coordinator container. Packed queries, scales and head weights exactly match the container's reference-checked native vectors. Checks cover execute/capture/replay, changed inputs, row-count mismatch, missing/duplicate graphs, clear/recapture, output invalidation and recovery, unsupported producer layers/capacities, one-byte-short budgets, and two independently captured waves sharing weights at capacity 16 for every producing layer. Payload staging is bounded at 1 MiB in this fixture. The fixture is intentionally outside Git; the reusable numerical qualifier is tracked.

Extracting the common FP4 packing helper leaves the existing source-key packer byte-exact against the official quantizer: all nine regression cases pass on each GPU, including every finite BF16 encoding and rounding midpoints. Native library, daemon and owner fixture builds pass. Adjacent JSON records source, binary, build, vector, fixture and result hashes.

Production scheduling, candidate sharing, proposal overlays, persistent FP8 serving KV, sparse attention, full-model correctness and throughput remain open. These component results establish no full-model speed claim.

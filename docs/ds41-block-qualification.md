# Backbone block sequencing

`BackboneBlockWave` owns the attention and FFN mHC boundaries for one backbone layer. It sequences `begin_attention` → `begin_ffn` → `finish_ffn` and publishes the final residual/pre-mix only after completion. It adds no device storage beyond its two boundaries: 225,504 bytes per capacity row, or 18,040,320 bytes at80. Shared mHC weights remain separately budgeted.

`begin_attention` collapses and normalizes the supplied residual with the incoming pre-mix, copies that input into the real query producer and records the resulting unique query execution ID and tokens. The query's normalized hidden input can also feed window/compressor production. The projected attention output now retains that execution ID through inverse rotary and both output projections. `begin_ffn` requires the exact pending execution, applies attention post-mixing, copies the resulting residual and attention-produced pre-mix into the FFN boundary, and prepares its normalized input. The returned FFN input includes the binding and borrowed residual/pre-mix views. `finish_ffn` requires that binding and a completed FFN result, then publishes the expanded residual and FFN-produced pre-mix for the next layer.

Wrong phases, stale attention results, mismatched FFN bindings and copy/launch failures reset block publication. Completing twice cannot expose an old result. Inputs, returned views and external FFN results retain explicit device/order/immutability contracts. Engram updates and dSpark tap reads still belong before block attention at the caller. The owner does not implement a replacement FFN or bypass expert execution.

## Qualification and numerical limits

Daemon and composed-fixture builds pass. Both RTX PRO 6000 Blackwell GPUs pass layers **0,2,7,8,14,20,24,39**, each with 16 requests, 129 committed tokens and five private proposed tokens. Real mHC-normalized inputs now drive query/window/source production, learned indexing, sparse attention and grouped output projection. Histories and incoming residuals are controlled fixtures, so these are representative layer paths rather than a complete 40-layer model.

The external driver uses an **explicit identity FFN fixture** to check FFN preparation and post-mixing. Production code accepts an externally completed shared+routed FFN result and does not contain this identity operation. Consequently these results do not qualify MoE execution or full-model output. Phase checks cover duplicate finish, stale projected attention after a fresh query, reset/publication and the previously qualified request/source/selection rejection cases. Exact and one-byte-short block budgets are checked.

The attention oracle passes every coordinate of 640 rows per GPU at `rtol=0.008, atol=0.002`, with maximum absolute difference 0.00390625. Output projection qualification passes 16 sets per GPU: inverse rotary is exact, grouped projection has zero observed difference and final projection has maximum absolute difference 0.0078125 under the same tolerance. All 1,224 payload hashes per GPU from those reports were checked against the final fixture dumps after adding FFN handoff views; none changed.

`qualify-ds41-block.py` uses the actual reference mHC methods/Sinkhorn kernel to check the block handoffs. Attention input normalization has zero observed difference. The attention-to-FFN residual passes BF16 tolerance with maximum absolute difference 0.0078125, and its incoming FP32 pre-mix passes `rtol=atol=2e-5` with maximum absolute difference 4.172325134277344e-7. On the exact handed-off FFN inputs, normalization and final residual pass BF16 tolerance (maxima 0.001953125 and 0.0078125); next pre coefficients pass the original FP32 tolerance with maximum absolute difference 9.5367431640625e-7.

**The stricter chained comparison did not pass:** when the FFN coefficients are computed from the independently rounded reference attention residual, one of 320 layer-20 coefficients exceeds the per-operation `2e-5` tolerance, differing by 4.951655864715576e-5. Both GPUs reproduce this. The qualifier retains that cumulative measurement and counts the out-of-tolerance entries; it does not relax the identical-input coefficient tolerance or claim full chained equality. The initial failed comparison logs are hashed in the record. This establishes a BF16-intermediate sensitivity that must be considered in full-model numerical qualification, not evidence that full-model correctness is complete.

Adjacent JSON records source, build, fixture, failure and final result hashes. Small drivers/vectors remain external. Shared/routed FFN production, four-Spark execution, engram/CED orchestration, scheduler-wide transactions, dSpark FP8 storage/verification, vision and full-model correctness/performance remain open.

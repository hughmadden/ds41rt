# Backbone cache bank lifecycle qualification

`BackboneCache` owns each request's 40 FP8 window leases and four paired compressed KV/index source leases under one generation-checked admission slot. Up to 16 requests share the bank. Source page budgets remain independently specified for layers 2, 8, 14 and 20. Construction checks the combined device allocation budget before allocation; model weights, proposal workspaces and host staging are separate budgets.

Batch planning derives request IDs, contiguous positions, expert row metadata and exact component chunks from the admitted requests. It rejects duplicate requests, zero-length chunks, more than 4096 combined rows and context beyond 1,048,576 tokens. Access and commit validate the bank identity, request generation, batch version and matching committed positions across all 44 components. Owned batch metadata is a snapshot; callers must validate against the bank before scheduling it.

Commit preflights all 40 window and four compressor proposals against exact lease/order/position/count metadata before writing. Every component receives the same accepted prefixes. Root history advances only after all commits succeed, including a version increment for zero acceptance. An execution error revokes every participating request and releases its component caches; cleanup failure poisons the bank. This is request invalidation, not rollback for retry. Consumers must finish before commit or release. The enclosing scheduler must still associate the actual token inputs and handle engram/dSpark acceptance as part of its wider transaction.

The retained `request_bank_lifecycle_and_batch_isolation` test passed on ostrich's GB10 using real CUDA allocations and the native library. Two cycles exercised 16 simultaneous requests, all 44 component identities, slot reuse, stale/foreign leases and batches, duplicate request IDs, invalid release preflight, missing commit producers, layer bounds, zero/oversized batch rejection and the 4096-row planning boundary. Releasing one request invalidated its old batch while the other 15 remained usable. Runtime was 0.37 seconds. The production daemon also built successfully.

This qualifies admission and metadata/device-state lifecycle only. Accepted-prefix execution across all 44 producers, failure injection during GPU commit, index/lane composition and full scheduler behavior remain unqualified. The Spark library lacks the SM120 FP8 projection AOT required to construct window producers, and the RTX driver/library mismatch remains unresolved. No model-output, throughput or full-model-fit claim follows from this test.

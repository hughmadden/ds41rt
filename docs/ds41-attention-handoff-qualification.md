# Real query/index/attention/output handoffs

The backbone attention components now provide typed handoffs from real query production through learned indexing, cache selection, sparse attention and output projection. A completed token-bound query has a unique checked execution ID and the exact host token list uploaded for that execution. Legacy raw-input component entrypoints remain available for primitive qualification, but their outputs have no query identity and cannot enter the new bound path.

`AttentionQueryWave::execute_tokens` uploads validated positions, captures or replays the appropriate live row count, then publishes the query identity and token list. `IndexQueryWave::execute_attention` copies that query's normalized rank, hidden input and positions into its own storage and propagates the identity. Selection checks the supplied proposal/token order against the actual query producer's token list, retaining its identity alongside the existing exact compressor snapshot bindings.

`SparseAttentionWave::execute_query` verifies query row/token order, then uses its rotated query output. At an index-producing layer, selection must belong to that exact query execution. Intermediate layers reuse selection from the nearest index producer, with the existing source-snapshot and token checks still applied. The completed attention result retains the query identity and tokens. `AttentionOutputWave::execute_attention` requires a bound result from its own layer and obtains both its input and inverse-rotary positions from that result. An unbound raw attention output is rejected.

Every handoff completes its copies before downstream execution. The stages currently use separate captured graphs and synchronous device copies; this is not a fused graph or an overlap/performance claim. Existing wave allocations remain unchanged apart from small host token/identity metadata. Capture reuse still depends on live rows and the cache addresses/shapes captured by each owner. Failed preparations invalidate publication where applicable, and fresh query executions cannot silently reuse an old same-layer selection.

## Qualification

The daemon and external composed fixture build successfully. Both RTX PRO 6000 Blackwell GPUs pass layers **0, 2, 7, 8, 14, 20, 24 and 39**, each with 16 requests, 129 committed tokens per request and five private proposed tokens. All query projections, window/source production, learned index queries, selection, attention sinks and output projections use real checkpoint weights. Attention queries now come from `AttentionQueryWave`; the earlier synthetic query injection is removed. Hidden inputs are controlled fixtures, so this is not execution of the full 40-layer model.

Coverage includes all four compressed sources, layer-7 index reuse, source-20 candidate sharing, later index producers 24/36, independent window/source slot permutations, ring wraparound and partial ratio-two groups. Replay and recovery remain exact. The fixture rejects rival compressor snapshots, another request's source, wrong window layers, duplicate requests, reordered query tokens, and a fresh query execution paired with older same-layer selection. Output projection rejects a legacy unbound attention result. The window-only 80→5→80 resize check still passes.

The existing owner qualifier independently resolves every selected/cache/proposal row and computes the 64-key blockwise attention arithmetic from the real produced queries. Every coordinate of 640 attention rows per GPU passes `rtol=0.008, atol=0.002`; maximum absolute difference is 0.0078125 on both GPUs. The output qualifier checks 16 final-stage sets per GPU (eight layers, two executions): inverse rotary is exact, grouped projection has zero observed difference, and final FP8 projection passes the same tolerance with maximum absolute difference 0.0078125. The final GEMM comparison takes the native grouped intermediate, as in its component qualification. These stage checks do not establish full-forward reference equivalence from the original hidden input or full-model logits.

`qualify-ds41-attention-output.py` now accepts optional layer/capacity selections for composed fixtures; its original full qualification defaults are unchanged. Adjacent JSON records source, fixture, build and result hashes. Temporary drivers and vectors remain outside Git.

Backbone mHC/CED/engram/routing composition, scheduler-wide accepted-prefix transactions, four-Spark execution, dSpark FP8 storage and target verification, vision, full-model correctness and measured throughput remain open.

# Target head implementation and partial qualification

`v41_target_head.rs` owns the final target mHC collapse, RMS normalization with epsilon 1e-20, and FP32 vocabulary logits. It retains only the 10,240-byte `norm.weight` tensor and borrows the existing 1,323,827,200-byte BF16 vocabulary head shared with dSpark. Each independent wave owns its stream, cuBLAS handle, 4 MiB workspace, captured graph and stable buffers. Wave budgets are 4,772,880 bytes for one row, 13,451,520 for 16 and 50,480,384 for 80.

Completed backbone outputs retain their execution binding. The head accepts only layer 39, validates source extents and devices, rejects empty, duplicate and out-of-range selections, and copies selected rows in the requested order. Consecutive selections use coalesced copies. Changing the selected row count recaptures the graph. Published logits carry the original binding, selected row indices and token positions. Raw component execution remains unbound; failed calls unpublish results and queued work drains before storage is released.

The original cuBLAS BF16 tensor-op projection failed the strict `rtol=2e-5, atol=2e-5` logit comparison on real checkpoint weights at 80 rows on both RTX GPUs. An independent FP64 oracle confirmed excessive accumulation error: maximum absolute native error was 0.000209808349609375, versus 0.00002288818359375 for the official FP32 projection. These are maximum errors across all coordinates, not the tolerance used for every coordinate. Splitting the native projection into at most 16 rows did not solve the problem consistently: the Spark check still failed at 16 rows. That workaround was removed.

The shared native vocabulary projection now uses `CUBLAS_COMPUTE_32F_PEDANTIC` with BF16 resident weights. The separate width-256 Markov projection keeps its previous compute mode. On ostrich's GB10, the rebuilt production native library and target-head owner passed two changed inputs each at 1, 16 and 80 rows. Each case exercised two independent waves, graph replay, byte-identical results, and budget/invalid-row/unpublished-output guards. All six numerical payload sets passed the unchanged logit tolerance against both the hash-locked official FP32 projection and an FP64 oracle. Collapse and normalization retain `rtol=0.008, atol=0.002`. Inputs come from earlier real-weight block fixtures with controlled residual/history inputs; they are not tokenized full-model prompts.

An isolated cuBLAS probe measured roughly 7.8 ms at one row, 13.2 ms at 16 and 26.5 ms at 80 on GB10, averaging ten launches per input with CUDA events. These are diagnostic Spark measurements, not RTX serving performance or end-to-end throughput. The component remains intended for RTX placement.

The Rust daemon and SM120/SM121 native libraries build. Final RTX execution is pending: the host's loaded NVIDIA kernel driver is 595.71.05 while an unattended upgrade installed 595.91.07 libraries, and NVML fails initialization. Earlier RTX owner checks passed with the original projection, including layer-39 selections of all 80 rows, last positions, reversed last positions, a single row and graph recapture, plus rejection of layer 20. Those checks do not qualify the final native projection. Repeat the RTX owner/numerical runs and dSpark projection regressions after the driver is restored.

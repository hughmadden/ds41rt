# Native V4.1 expert launch bridge

The production Rust FFI can initialize and launch role-specific V4.1 expert AOT variants through a stable C interface. All dSpark experts use the coordinator RTX variant (128 experts, intermediate 2304, top-3); backbone Spark variants use 384 experts, logical TP intermediate 576, padded execution intermediate 640, top-6.

The exporter checks the generated launch parameter names, pointer/scalar types and single-pointer tensor layouts before emitting the native dispatch table. Four intentional ABI mutations were rejected. C initialization checks compute capability and physical SM count, binds each variant to its first device, and retains CUDA modules until library unload. Launch checks handles, capacity, planned scalar controls and non-null slots. Rust borrows the library for each handle; its unsafe launch contract requires correct buffer layout, initialization, ownership and lifetime through graph replay.

Both native builds completed. M16 numerical and mutated-input graph checks passed through the production Rust argument builder and C bridge on local RTX 0 and ostrich GB10. The Rust builder supplied the manifest defaults of 188 and 48 active clusters respectively. The existing independent expert fixture retained relative-L2 < 0.01 and cosine > 0.9999 gates, and checked graph replay without allocation. The Rust ABI layout/capacity unit check passed. Exact source/artifact hashes and captured results are in `ds41-native-expert-bridge-qualification.json`.

These are component checks. The temporary Rust cdylib fixture still receives Python-prepared packed weights and scratch, and final route reduction still uses a Python-launched GPU kernel. Production native weight preparation, scratch ownership, reduction export, route-plane transport and model execution remain open. Capacities 1/16/80/256/1024/4096 build, but this bridge execution evidence covers only M16. Full containers and serving scripts have not been requalified at this revision.

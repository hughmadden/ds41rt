# Adjacent-block preparation and engram ordering

`BackboneBlockWave::initialize_previous` copies a completed predecessor's residual and incoming pre-mix into the next block's stable input buffers. It checks adjacency, predecessor query-binding layer, row capacity, absolute positions, exact extents and device before copying. Prepared inputs retain the predecessor binding and token positions; block output remains unpublished.

Layers 1 and 14 enter an engram-pending state. `apply_engram` checks the gate's actual backbone layer and gathered row count, executes the captured gate, copies the updated residual back, and preserves the incoming pre-mix. Only successful completion makes the prepared input available. Failure resets the block. A second engram application or an application at a layer without pending engram is rejected by the phase check.

`begin_prepared_attention` consumes the prepared positions through the existing query/attention entry. Its preparation check prevents this path from starting attention while engram is pending. The raw `begin_attention` API retains its explicit caller-managed input contract. Gathered engram rows, image masks and request histories must still be associated with the correct packed batch by the scheduler; this remains an unsafe caller contract, not a new request-history proof.

`PreparedBlockInput` exposes the post-engram, pre-attention residual. The dSpark main-context adapter accepts this view and derives tap layer and row count from it, checking predecessor layer, extent and device before dispatching the existing tap kernel. The caller must preserve the same request order across layers 37, 38 and 39 and complete tap reads before reusing block storage.

`EngramGate::execute_captured` owns first capture and shape recapture, then replays against staged inputs. Its execute/replay paths now attempt stream synchronization even when a kernel enqueue or graph launch returns an error, leaving output unpublished on failure. The projection and gate arithmetic are unchanged. Readiness-time graph preparation still belongs to model integration.

The daemon builds with these paths. An external Spark fixture exercised all 39 adjacent-layer transitions at 80 rows using real boundary-weight owners and controlled predecessor values. The fixture constructs predecessor bindings inside its private copy of the block module; it does not execute the preceding blocks. Residual/pre copies were byte-exact for every transition. The two engram layers withheld prepared views; the other layers retained exact positions and predecessor identity. Nonadjacent layers, undersized blocks, invalid pre extents, different devices and out-of-range positions were rejected. Reset and rejected initialization left prepared inputs and block outputs unpublished.

For layers 37–39, the fixture fed distinct rotated rows from checkpoint-backed embedding vectors into the prepared views and invoked the native tap operation. All three mean-stream segments matched their expected bytes and order exactly. This tests prepared-view consumption by the native tap, not the owning dSpark main-context adapter's complete execution.

The adjacent JSON records source/artifact hashes and terminal logs. The fixture remains under `/tmp/ds41-block-transition`. Chained engram execution, `begin_prepared_attention` through real query projection, and the owned dSpark tap adapter are compiled but await RTX validation. The FP8 AOT exporter explicitly requires SM120; the coordinator's NVIDIA kernel/library mismatch remains unresolved. Full CED execution, scheduler integration and model/performance qualification remain open.

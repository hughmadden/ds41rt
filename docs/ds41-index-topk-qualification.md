# Bounded tiled index top-512

`ds41rt_v41_index_top512`, exposed through `V41IndexTopK`, selects from FP32 index scores and explicit U64 logical row IDs. It accepts 1–4096 queries and 1–16,384 candidates per call. An opaque 512-entry U64 accumulator per query retains the highest-ranked candidates across disjoint tiles. `reset=true` starts a new search without reading prior accumulator contents; continuation requires the same query bindings and scoring inputs. Valid positions must be unique across the complete search. The accumulator is private execution state, not committed model cache.

Each block sorts 1024 score/position keys and retains 512. Pairwise merges reduce the tile to 512, then a final merge combines it with the previous accumulator. Selected logical positions are sorted ascending into fixed-width I32 output, with trailing `-1` padding. Logical positions have no attention-cache concatenation offset added. Invalid IDs at or beyond 1,048,576, NaNs and negative infinity are ignored; positive infinity is valid. Both signed zeros rank equally.

Ranking is descending score, then ascending logical position. The latter is an explicit deterministic tie policy: tied results are not claimed bitwise identical to a particular PyTorch `topk` invocation. Untied selection matches the reference operation; tied sets obey the same score ranking while making the result independent of tile order and partition. Full-model qualification must still assess resulting attention/logit behavior where scores tie.

Scratch is caller-owned and bounded by `queries * ceil(candidates / 1024) * 512 * 8 * 2` bytes. At a 16,384-candidate tile this is 131,072 bytes per query, plus 4096 accumulator bytes and 2048 output bytes. Scratch need not scale with total history length. No allocation or host synchronization occurs inside the native operation. It validates shapes, reset mode, scratch size, pointer alignment/overflow and all buffer overlaps; the Rust wrapper additionally checks buffer lengths and matching device IDs. Query/request lifecycle validation remains the responsibility of the owning execution path.

`scripts/qualify-ds41-index-topk.py` passes 13 cases on each RTX PRO 6000 Blackwell. Twelve shape cases cover candidate counts 1/511/512/513/1023/1024/1025/2049/6145/4095/16384, and query counts through 4096. Odd merge counts, short tail blocks and both sides of the 512 boundary are included. Untied scores match direct PyTorch `topk` followed by position sorting. Tied scores match an independent stable lexicographic oracle. Tests include signed zeros, positive/negative infinity, NaNs, invalid positions, dirty accumulators on reset, changed-input captured replay, empty results and shape/pointer/overlap/scratch guards.

The thirteenth case selects from all 1,048,576 possible logical positions with tied scores, streaming through 64 tiles of 16,384 candidates. Forward order, reverse order and uneven 8191-candidate partitions produce identical outputs and accumulator bytes. A captured full traversal also matches the oracle after changing scores. The qualification creates a complete score array for its independent oracle; production selection itself only requires a tile and its bounded accumulator. This verifies full-history selection, not full-history model scoring or attention performance.

The real-weight compressor fixture passes all 55 cases on both GPUs. Its four source-layer page-reuse cases now capture paged index scoring and top-512 selection together against committed real-weight-generated keys in physical page order `[1,0]`. Synthetic unit query/head weights give an independent decoded-key score oracle. Four unique reachable candidate positions survive in ascending order; future/sentinel candidates are padded out. Changed causal metadata makes both the captured scorer and selector produce an empty result. The Rust wrapper's undersized scratch guard is also exercised. Query/weight projection and a complete real-model attention distribution are outside this fixture.

Native library, daemon and external fixture builds pass. Adjacent JSON records source, build, fixture and log hashes. The reusable selector qualifier is tracked; the owner fixture remains under `/tmp/ds41-compressor-owner` and is not shipped code.

Hierarchical block scoring/top-2048 selection, query production, proposal overlays, persistent FP8 KV, attention integration, request-owned selection scheduling and full-model correctness/performance remain open. No throughput claim follows from these numerical/component checks.

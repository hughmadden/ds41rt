# Owned dSpark attention wave qualification

`DsparkAttentionWave` now executes query A, query normalization, query B, forward RoPE, KV projection, fused KV normalization/rotation/quantization, attention and the complete inverse-RoPE/grouped-output-A/FP8-output-B chain on one owned stream. Query-normalization and grouped-projection outputs reuse child projection storage. Private draft KV remains separate from committed rings. The caller supplies normalized hidden rows and per-row complex frequencies; frequency generation, main-hidden projection/cache production and the outer mHC boundary are not included yet.

The fused KV operation preserves BF16 rounding after normalization and again after rotation, then applies official K32 activation scaling with the 1e-4 maximum floor and UE8 scales before FP8 quantize/dequantize back to BF16. On both RTX GPUs, its tiny/random/zero and changed-input graph cases are bitwise equal to separate native norm/RoPE followed by reference-formula quantization; the separate norm/RoPE operations retain their earlier numerical reference checks. The expanded primitive qualifier has 54 cases per GPU.

Each request supplies a generation-checked window lease and expected committed end. Whole-batch validation rejects duplicate slots, stale/released/foreign leases, unseeded windows, changed positions, empty/oversized batches and draft-position overflow before descriptor upload. A captured graph records its cache owner's unique identity and request count; replay revalidates that identity and all current leases. The immutable window borrow lasts through synchronous GPU completion. A graph may outlive a freed window only as inert metadata; it cannot replay against a different owner, and graph destruction does not read the old ring.

The first owner run exposed an incorrect use of five/fifteen live rows as AOT capacities. Admission now selects existing 16- or 80-row storage buckets and launches the actual live count; no new runtime specialization is needed. Capture warms the complete chain, suppresses warmup publication and closes capture on every error path. Execute/replay drain submitted work before publication, errors invalidate readiness, and destruction drains and destroys the graph before freeing children.

A native-format sparse synthetic checkpoint exercises all three stages at one, three and sixteen requests on both RTX PRO 6000 GPUs. It contains nonzero stage/group-specific output weights, nonzero query/KV weights, stage-specific norms and varying per-head sinks. Two cases change hidden inputs, rotary positions, committed contents and request order. Committed ends range from 2 through 131000, covering partial windows, wraparound and nonzero-position tail seeds. The fixture verifies that attention leaves every byte of the committed ring unchanged.

The independent expected-value generator uses exact constant-weight projection algebra, the pinned rotary function, blockwise attention reference math, grouped BF16 rounding and K32 FP8 output-input quantization. All 600 expected row scalars are nonzero, ranging from -288 to 288; they expand to 3,072,000 checked BF16 output elements per GPU. The observed final outputs are bitwise equal in all eighteen structured cases per GPU, though the comparison contract remains 0.008 relative/0.002 absolute tolerance and arbitrary full-model values are not claimed bitwise equivalent. Position/lease/capture-owner errors, budget guards and recovery also pass.

An owner reserves 8,934,544 device bytes for one request, 9,600,144 for three, or 31,235,216 for sixteen, plus 128 pinned bytes. The new query/private-KV/descriptor storage adds 15,974,784 bytes per three-stage capacity-80 wave beyond already budgeted projections and output owners. The partial two-wave dSpark admission total is now 8,843,334,488 device bytes; remaining producers/frequency and larger prefill storage, shared vocabulary residency and driver/graph overhead remain separate.

The native and daemon builds pass against the corrected b12x master pin. Exact sources, binary hashes, primitive results, fixture inputs and owned logs are recorded in `ds41-attention-wave-qualification.json`. Full-stage sequencing, verification, serving integration and alternating-wave overlap remain unfinished, and no performance or full-model quality claim is made.

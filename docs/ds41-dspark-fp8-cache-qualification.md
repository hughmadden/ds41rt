# Packed dSpark committed KV

The dSpark committed window now stores each row as 512 E4M3 value bytes followed by 16 E8M0 scales, one per 32 coordinates. The previous implementation quantized the same values but persisted their BF16 expansion. The writer now retains the packed representation and attention reconstructs BF16 values only while filling its existing shared-memory tile. The quantization scale, rotary treatment, physical ring order, 64-key softmax boundaries and BF16 probability rounding are unchanged. Private draft intermediates and projection staging remain temporary BF16 computation buffers.

Each 128-row request ring uses 67,584 bytes instead of 131,072. Sixteen slots use 1,081,344 bytes per stage, saving 3,047,424 bytes across all three stages. Including the unchanged 4,096-row BF16 staging allocation and 384-byte descriptor array, each maximum-size cache owner uses 5,276,032 device bytes and 384 pinned bytes. The owner and FFI checks share the new row/slot constants.

The native entry points are now `ds41rt_v41_dspark_cache_write_fp8` and `ds41rt_v41_dspark_attention_fp8`. The Rust loaders require these names. An older native library exposes neither and cannot silently interpret packed storage as BF16. Historical BF16 entry points are not retained in the new library.

On ostrich's GB10, the production cache owner passed exact packed-byte comparisons against an independent CPU quantizer for all 4,096 source rows, including zero, signed zero, small values and finite BF16 extremes. This is a storage test; it does not assert finite attention output for extreme values after quantization. Mixed lengths around 128 and 256, overwritten-prefix elimination, 64-bit position seeding, changed batches, ring wraparound and rejected writes also passed. Invalid budgets, duplicate/occupied slots, noncontiguous appends, overflowing positions/source spans, incomplete seeds, stale generations and foreign leases were rejected without corrupting admitted contents.

`scripts/qualify-ds41-dspark-attention.py` passed its blockwise reference-math comparisons at 1, 3 and 16 requests, with two changed inputs each and captured replay. It feeds packed committed values and independently reconstructs the BF16 oracle input. Checks include poisoned unused rows, all five private draft positions, private-only attention, sink behavior, probability rounding and invalid descriptor/host arguments. Tolerances remain `rtol=0.008, atol=0.002`. A separate transition check loaded the preceding BF16 native library and found bit-exact attention outputs for all six changed-input cases. It also verified the old library lacks both new packed symbols.

The daemon and SM120/SM121 native libraries build. The adjacent JSON records source/artifact hashes, successful run logs and attention results. Cache-owner and transition fixtures remain outside the repository under `/tmp/ds41-dspark-fp8`.

This is Spark component qualification. RTX cache and complete dSpark graph requalification remain pending because the host's NVIDIA kernel/library versions still differ. Full-model scheduling, proposal verification and performance are not established by these checks.

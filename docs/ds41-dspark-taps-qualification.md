# dSpark decoder-tap gather

The pinned reference takes `h.mean(dim=2)` after a target layer's engram update and before its attention, then concatenates target layers 37/38/39. The native gather reads BF16 `[rows,4,5120]`, accumulates the four streams sequentially in FP32, scales by one quarter, rounds once to BF16 and writes directly into that layer's slice of the stable `[rows,15360]` main-projection input. Other tap slices remain unchanged.

The Rust `DsparkMainContext::enqueue_tap` interface writes that existing input on a caller-provided stream and can be included in the backbone graph. It invalidates previously published main output, validates layer and row geometry through the native binding, and adds no persistent allocation or intermediate copy. The caller must preserve packed row order, supply post-engram/pre-attention streams, and retain/serialize input and owner storage through completion and graph replay before main-context execution consumes all three taps.

The standalone qualifier passed on both RTX PRO 6000 GPUs at 1, 13, 73, 255, 1001, 4095 and 4096 rows. Initial execution and changed-input graph replay matched the hash-verified reference's CUDA mean bitwise, including mixed magnitudes, zero rows and cancellation-heavy values. Layer order 39/37/38 verified independent slice placement and preservation of other slices; overlapping storage, invalid layers and invalid rows were rejected. An exploratory wide-magnitude probe found pairwise reductions differed from the reference, motivating explicit sequential FP32 addition.

The updated temporary Rust main-context fixture passed on both GPUs at compiled capacities 1/16/80/256/1024/4096 with live rows 1/13/73/255/1001/4095. It now supplies the packed input through `enqueue_tap` and checks it before main projection, normalization, native frequencies, all three independent KV projections and committed-ring scatter. Both initial and changed-input/replay cases matched their structured expected BF16 outputs bitwise, while existing commit/budget/lease guards remained active. The standalone test covers unequal streams; the composed fixture repeats each expected tap across the four streams to isolate placement and downstream integration.

Native and daemon builds passed. An initial fixture compilation failed because a manually narrowed buffer omitted its device metadata; the corrected fixture preserves all buffer fields and only final run logs are counted here. This qualification uses synthetic weights, does not measure throughput, and does not yet connect production backbone layer call sites or complete three-stage draft verification. The partial two-wave device estimate remains 8,853,577,584 bytes.

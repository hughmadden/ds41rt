# dSpark committed main-context qualification

The owned producer implements the pinned reference's shared `main_norm(main_proj(concat(taps)))`, then each stage's independent `wkv`, KV RMSNorm and forward RoPE on one stream and one captured graph. Final K32 FP8 quantization/dequantization runs once in the existing ring scatter, preserving the BF16 norm and rotation boundaries.

Both RTX PRO 6000 GPUs passed six compiled capacities (1, 16, 80, 256, 1024, 4096) with live row counts (1, 13, 73, 255, 1001, 4095), initial execution and changed-input graph replay. All compared normalized hidden values and newly committed ring values matched bitwise in these structured fixtures. This is correctness evidence for this composition, not a throughput measurement or full-checkpoint qualification.

Synthetic FP8 main weights use scale 2^-7 with a 1.25 main norm; stage KV weights alternate 1 and 1.5 by output channel, use distinct power-of-two scales, and stage norms are 1, 1.25 and 1.5. Distinct tap values cover nonzero inputs, cancellation and zero rows. The independent PyTorch oracle applies explicit K32 E4M3/UE8 activation quantization, BF16 projection/norm boundaries and rotary functions extracted from the hash-verified official reference. Sparse checkpoint files contain synthetic payloads only.

Each commit prevalidates all three stage batches against the produced live row count, generation-checked leases, contiguous positions and corresponding logical request IDs/row mappings. Tests reject an invalid final-stage source span and swapped final-stage request leases before any logical committed end changes. Budget-minus-one, unsupported capacities, duplicate capture, unpublished warmup, consumed output, zero rows and mismatched replay rows are also checked. Tests cover initial seeding, appends and physical ring wraparound. GPU fault injection was not performed; the error path invalidates all participating leases if any stage's copy/scatter fails.

The owner needs 9,724,944 device bytes at capacity 80 and 495,452,176 at capacity 4096; the capacity-80 wave plan adds 5,118,988 bytes beyond the already-counted main projection because committed KV projections have separate scratch from draft attention. The partial two-wave dSpark device estimate is now 8,853,572,464 bytes. This still excludes the shared vocabulary head and driver allocations; larger prefill producer capacities must be budgeted explicitly.

The final daemon and fixture builds passed. Native kernels were unchanged, using the existing master-pinned AOT library. The producer still receives caller-supplied tap rows and frequencies; decoder-tap gathering, native frequency production, complete attention/mHC/stage sequencing, verification rollback and serving integration remain open.

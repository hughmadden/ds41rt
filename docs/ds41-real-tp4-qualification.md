# Real checkpoint FFNs across four Sparks

Real backbone layers 0, 20 and 39 now pass through the existing block-bound router, four Spark TP workers, RTX shared expert, ordered route reduction and final mHC boundary. This replaces analytical rank responses in the preceding handoff qualification with actual official checkpoint expert computation on ostrich, dodo, emu and kiwi. The reusable numerical checker is `scripts/qualify-ds41-real-tp4.py`.

Each layer runs two 80-row batches representing 16 requests with five tokens each, changing the text/image routing mask. Inputs come from the real attention/mHC component fixture with controlled starting residuals and cache history; these are not tokenized full-model prompts. All 384 experts' native tensors for that layer are loaded and packed on every rank, with a logical intermediate slice of 576 padded to 640 by the qualified kernel. Each rank retains 2,005,401,600 packed weight bytes and uses capacity-80 execution scratch. Layers are tested sequentially rather than retaining all 40 layers.

The RTX client produces real query, attention, projection, mHC, shared-expert and router results, generates an immutable bound request, and sends it through `NativeTp4Wave::execute_ffn`. Each Spark uses the production `ExpertWeights` loader and `ExpertExecution::execute_host_request`. Seven-row response chunks exercise the existing TP4 receiver. Every rank records the exact received frame and FP32 route plane. The checker verifies all four frames match the generated request, reproduces ordered rank/route reduction from those planes, adds the actual shared result, and requires byte-exact equality with the RTX output.

The official hash-locked `Expert.forward` and TileLang FP4 GEMMs independently compute every selected expert. The K32 activation quantizer retains the documented `tir.disable_vectorize` workaround for TileLang 0.1.8's shared-memory aliasing race. No model arithmetic is changed. Reference comparisons include each active expert, the complete route tensor and final shared+routed FFN, using the existing relative-L2 < 0.01 and cosine > 0.9999 gates.

All six batches passed. Layer 39's larger absolute differences reflect the magnitude of this controlled fixture's activations; both absolute and relative results are retained. Across the three layers, 330 distinct selected experts and 2,880 token/expert routes were checked. `qualify-ds41-block.py --layers 0 20 39 --ffn-result` also passes the final mHC output and new mixing coefficients against the reference using the actual FFN result. Thirty router payloads and thirty shared-expert payloads match the previously qualified handoff records exactly. This preserves the previously recorded chained BF16 coefficient sensitivity; full-model numerical accuracy is still unproven.

## Build and startup observations

The Spark native library was rebuilt on ostrich for SM121 from the current source and b12x master revision `aeb1d8c18e99809797c76af6fbfaca1273c36ff6`. The current Rust worker was built natively and the same library and executable distributed to all four Sparks. The initial temporary Cargo mount was read-only and prevented lockfile creation; rebuilding with a writable fixture mount passed. Three initial worker launches stopped because the development image tag was absent. The same development image was then distributed and its digest verified on all four hosts: `sha256:a641a14143728cefc9989807c92b6aff59858adb64d835c7033183148894152d`. These fixes concern development fixture deployment; the release scripts and full serving containers remain to be qualified.

Weight loading and execution setup are timed separately. Layer 0 loaded in 0.671–0.788 seconds per rank, layer 20 in 3.001–3.299 seconds, and layer 39 in 0.661–0.693 seconds. Catalog validation adds approximately 1.5 seconds in these runs. Execution scratch setup took 0.0022–0.0045 seconds; this does not measure full-model graph setup. First expert execution including host transfers took approximately 10–14 ms, and the second approximately 3–4 ms. These are diagnostic observations, not end-to-end throughput measurements.

Layer 39 additionally records `/proc/self/io`: approximately 3.61 GB of userspace reads and zero storage `read_bytes` during loading on every rank. It is therefore a cache-backed result, not evidence of NVMe line rate. Native useful payload is 1,804,861,440 bytes per layer/rank, versus 2,005,401,600 packed resident bytes; strided W2 selection reads more source bytes than its useful TP slice. Layer 20 has no physical-I/O counter record, so its cache/storage contribution is unresolved. Cold full-checkpoint loading, physical read amplification and the complete startup budget remain open optimization/qualification work.

All worker and client processes completed successfully, all temporary worker containers exited, and all four Spark GPUs were idle afterward. `ds41-real-tp4-qualification.json` records sources, artifacts, image digest, received-frame/plane/checkpoint hashes, terminal logs, I/O counters and numerical results. Complete 40-layer execution, mapped-engram scheduling, dSpark verification, vision, API/scheduler integration and the requested throughput targets remain unqualified.

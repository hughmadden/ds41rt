# Native CSA2 compressor projection and pooling

The native compressor projects the official BF16 `[512,5120]` weights with FP32 accumulation and reduced-precision reduction disabled. Ratio-two KV and gate projections produce FP32 outputs without materializing expanded FP32 weights or inputs. Ratio one produces BF16 output directly and uses the existing V4.1 norm. This preserves the reference's precision boundaries, with GEMM reduction-order differences measured below rather than claimed bitwise equivalent.

Ratio-two pooling computes independent two-element softmax gates for each latent coordinate. The pooled value rounds to BF16 before RMS normalization with the official epsilon `1e-20`. The normalized, unrotated latent is suitable for the index-key producer before the later attention-side RoPE and cache quantization.

Each packed input row has a U64 predecessor descriptor: a committed pending-state slot, an earlier row in the current projection batch, or `UINT64_MAX` for an incomplete pair. Incomplete and invalid descriptors emit zero without reading invalid addresses. This supports single-token decode and arbitrary chunk boundaries without changing committed state during graph execution. The caller must validate logical request ownership, adjacency and positions before preparing descriptors, then commit only accepted projected KV/score rows. This primitive does not implement that host ownership policy itself.

Projection uses one caller-owned 4 MiB cuBLAS workspace per serialized handle. Pooling allocates no workspace and does not mutate input projections or pending state. Sixteen pending half-groups require 65,536 bytes for FP32 KV plus score; descriptors require eight bytes per input row. Native and Rust FFI guards enforce supported row counts up to 4096, slot counts up to 16, buffer spans, output/input disjointness and the projection handle's current device. Buffers and workspace must outlive captured graphs.

`scripts/qualify-ds41-compressor.py` reads and hashes the actual compressor weights at layers 2, 8, 14 and 20 from completed checkpoint `dba1be0a40aa45a94ad051997016db3960a90277`. These eleven BF16 tensors total 36,704,256 payload bytes; the rest of the model is not loaded. It extracts the pinned official `Compressor` and `RMSNorm` classes and supplies the official inference configuration and native checkpoint weights. Activations are synthetic and include tiny values.

Both RTX PRO 6000 GPUs pass 24 real-weight cases each: four source layers, request counts 1/3/16, and two sequence schedules. One schedule processes nine individual tokens; the other processes 199 tokens as chunks of 1/2/5/64/127. Completed latents are compared with official whole-sequence prefill; the chunk path carries odd trailing groups explicitly. Replaying the same graph is bitwise exact and leaves pending state unchanged until the fixture explicitly commits it. Changing predecessor descriptors under replay suppresses output as specified.

Projection-only FP32 results are checked against FP64 dots with absolute tolerance `1e-4` and relative tolerance `2e-5`. Pooling/norm checks use the actual native projections, isolating pooling from GEMM differences, with BF16 tolerances `.002` absolute and `.008` relative. The full real-weight compressor comparison uses `.004` absolute and `.016` relative. Maximum observed full-output absolute error is `0.015625`; outputs are not claimed bitwise identical to the reference. The adjacent JSON reports differing BF16 element counts and projection errors per case.

Four additional synthetic pooling cases per GPU cover row counts 1/16/80/4096, extreme and equal gates, tiny/zero values, graph replay, invalid 64-bit predecessor values, overlap rejection and slot-count rejection. Native CMake and daemon builds pass. Source, payload and result hashes are in the adjacent JSON.

This qualifies selected real-weight compressor computation. Production request leases, accepted-prefix commit/rollback, source/reindex/reuse ownership, index-key projection, compressed-cache RoPE/quantization, hierarchical selection, sparse attention and the backbone scheduler remain to be integrated and qualified. It does not establish full-model quality, startup speed or throughput.

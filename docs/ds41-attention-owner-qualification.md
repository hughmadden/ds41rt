# Owned window/source/selection attention

`v41_sparse_attention.rs` composes the native FP8 attention consumer with live window, compressor and index-selection outputs. One wave owns BF16 query/output buffers, device metadata, pinned metadata staging and a captured graph. Up to 16 requests share a launch sequence, with separate narrowed cache views and a total capacity of 1–4096 query rows. Device allocation is 131,152 bytes per capacity row: 10,492,160 bytes at 80 rows and 537,198,592 at 4096. The requested budget is checked before allocation.

Before enqueueing, the owner checks increasing positions and unique request IDs, matching window layer/pool, matching window/source request and committed token position, and the correct compressed source for the backbone layer. `IndexProposal` now carries a private request ID from its validated lease. Selection must come from the layer's nearest index producer and match every exact compressor proposal snapshot and token position. Thus layers between index producers reuse the same validated selection, while later index producers still require their own result against source-20 KV. Layers 0/1 require window-only execution.

Each request's window/source metadata is uploaded into the owned device buffer. Graph reuse checks layer, sink pointer, request row partitions, window widths, selected-output address and all captured cache/proposal addresses, sizes and capacities. Changed metadata uses replay; changed captured bindings trigger drained warmup and recapture. Completion always drains before returning an output. The output borrows the request/proposal and selection views, preventing their owners from committing, releasing or overwriting them while a consumer holds that output. Query activation and sink correspondence remain explicit unsafe caller contracts until their producers are composed.

## Qualification

The external fixture builds and passes on both RTX PRO 6000 Blackwell GPUs for layers **0, 2, 7, 8, 14, 20, 24 and 39**. Every case has 16 requests with permuted window/source slots, 129 committed tokens per request and five private proposed tokens, for 80 attention rows. This covers wrapped windows, all four real-weight compressor sources, prior incomplete ratio-two groups, layer-7 reuse of layer-2 selection, source-20 candidate sharing, and learned index producers 24/36 for later attention layers. Window/compressor/index-query/selection production and attention sinks use the official checkpoint. Attention queries are finite fixture data cycled from hidden inputs, not the still-unimplemented real backbone query projection.

Captured replay matches exactly. The fixture rejects rival compressor snapshots, window/source request mismatches, wrong window layers, duplicate requests and a one-byte-short allocation budget. A valid execution after rejected calls reproduces its previous result. Window-only execution also passes 80→5→80 row recapture with exact recovery.

`scripts/qualify-ds41-attention-owner.py` independently resolves every dumped selected row through host page tables and strided private proposals, dequantizes the exact FP8 buffers, and computes attention using the previously qualified blockwise arithmetic oracle. All 640 output rows per GPU, including every head and coordinate, pass `rtol=0.008, atol=0.002`. Maximum absolute difference is 0.0009765625 on each GPU. Replay/recovery dumps are compared exactly. This composition check uses the independent arithmetic oracle; execution of the actual pinned TileLang kernel is covered separately by `ds41-sparse-attention-qualification.md`.

Daemon and external owner-fixture builds pass. The adjacent JSON records source, build, fixture and result hashes. The reusable numerical qualifier is tracked; the small Rust driver and vectors remain outside Git.

This is a completed cache/selection consumer composition, not full backbone execution. Real attention query production, inverse rotary/output projections, backbone mHC/CED integration, scheduler-wide accepted-prefix transactions, dSpark FP8 storage, vision and full-model correctness/performance remain open. The compressed serving representation retains the documented FP8-policy difference from reference compressed FP4.

# Native V4.1 expert scratch preparation

The native expert dispatch table now includes all 44 pointer slots' scratch offsets from the pinned b12x planner, including shared base addresses for aliased packed-input and scale views. C and preloaded Rust entry points bind these views into caller-owned storage and initialize it on the supplied CUDA stream. External input and weight slots remain unchanged. Initialization zeros scratch and sets the native E8M0 recipe's input/down global scales to one; it runs once before use and graph capture, with caller-enforced stream ordering and exclusive scratch ownership.

The exporter rejects unknown/duplicate/missing scratch tensors, dtype or extent changes, overlapping/misaligned layout entries, unsupported initialization modes and inconsistent capacity. Additional validation added after the architecture builds regenerated byte-identical dispatch headers for both roles; six adversarial manifest mutations were rejected. Native binding checks initialized handles, alignment, capacity and address overflow before changing any pointer slots; device initialization also checks the current device against the kernel's device.

Both native architecture builds completed. On RTX 0 and ostrich GB10, all capacities 1/16/80/256/1024/4096 passed pointer binding checks, full-byte initialization checks (including alignment padding), trailing guard checks and rejected undersized/misaligned bindings. These checks initialize storage but do not launch every capacity's expert kernel.

The M16 expert numerical and changed-input graph fixture passed on both devices using separately allocated scratch initialized and bound through the production Rust API, followed by native expert execution and Rust/CUDA route reduction. Relative-L2 < 0.01 and cosine > 0.9999 gates and replay allocation checks remain unchanged. The Spark fixture validates one local intermediate-width-576 shard with prepared width 640; it supplies three zero planes to the TP4 reducer to compare the local shard result and does not qualify distributed TP execution. The RTX fixture uses the full dSpark intermediate width 2304 and top-3 routing. Rust daemon compilation passes with 427 existing warnings.

Python still allocates fixture buffers, prepares packed weights and constructs input routes. Production CUDA allocation ownership, native weight preparation/loading, per-route network transport and model scheduler integration remain open. Full containers, serving scripts and checkpoint execution are not qualified by these component results. Exact source/artifact hashes and results are in `ds41-native-expert-scratch-qualification.json`.

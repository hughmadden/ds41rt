# Backbone rotary frequencies and compressor handoff

The native backbone frequency kernel accepts packed U64 absolute token positions and emits FP32 complex RoPE64 values without allocating a context-sized frequency table. Layers 0/1 use the official pure-window base 10000. Layers 2–39 use base 160000 with YaRN original length 65536, factor 16, beta-fast 32 and beta-slow 1. The reference's host calculations set the interpolation boundaries to dimensions 15 and 25.

The CUDA operation order matters at long positions. The pinned reference's scalar division in the interpolation ramp uses reciprocal multiplication; replacing that with rounded division caused a phase difference at rotary dimension 24. The implementation now preserves the reciprocal multiply, separate additions/products and FP32 polar construction. Bounds, pointer alignment, output overlap and layer/row guards run before launch.

`scripts/qualify-ds41-backbone-frequencies.py` hash-checks the pinned model and inference configuration, extracts the official frequency function, and constructs its oracle on CUDA. Both RTX PRO 6000 GPUs pass 160 layer/row combinations: all forty backbone layers at 1/16/80/4096 rows. The checks include reordered packed positions, graph replay, the training-context boundary and the maximum tested context. For each of the two rotary modes, the 4096-row graph scans every position from 0 through 1,048,575. Across all these cases, maximum FP32 error and differing-element count are both zero. Invalid rows, layer IDs and output aliases are rejected.

`CompressorWave` now owns position and frequency buffers and computes these frequencies inside the existing proposal graph. Completed latents use their first represented token position from the validated compressor plan, not the compressed-row index. Non-completed rows use position zero and remain excluded by completed-row metadata. The output view exposes matching latent and frequency rows under the same lease/version validation and lifetime. Latents remain unrotated so the index-key projection can consume them before compressed-KV rotation.

On both GPUs, all fifty real-weight compressor owner regressions pass after this integration: forty-eight mixed-acceptance cases across the four sources and 1/3/16 requests, plus two full 4096-row prefill/replacement-tail cases. The driver additionally compares every frequency-buffer byte with independently generated official frequencies, including incomplete rows, changed packed request order, partial acceptance and ratio-two first-token positions. Existing numerical tolerances, stale-wave rejection and accepted-prefix checks are unchanged.

Frequency ownership adds 264 device bytes per capacity row: eight position bytes and 256 frequency bytes. Wave totals are now 5,444,864 bytes at 80 rows or 68,222,976 at 4096 for ratio two, and 5,198,464 or 55,607,296 for ratio one. Pending state and shared weights are unchanged. Pinned metadata is sixteen bytes per row for ratio two and eight for ratio one. These are component allocations, not final model memory-fit measurements.

Native, daemon and fixture builds pass. The adjacent JSON summarizes checked cases and records source, full-result, fixture and log hashes. Temporary owner vectors remain under `/tmp/ds41-compressor-owner`. Index-key projection, FP4 key/cache encoding, cache ownership/reuse, selection, sparse attention and complete backbone execution remain open; this is not full-model correctness or performance qualification.

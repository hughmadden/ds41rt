# Native V4.1 route reduction

`ds41rt_v41_reduce_routes_async` and the preloaded Rust `V41RouteReducer` replace Python-launched final reduction at the native expert boundary. The CUDA kernel supports RTX dSpark (one rank, top-3) and backbone TP4 (four ranks, top-6), both with hidden size 5120. It sums rank partials in FP32, rounds each completed expert to BF16, sums routes in FP32, adds optional shared BF16 output, and rounds the result to BF16. Explicit round-to-nearest adds prevent compiler reassociation across these boundaries.

The caller owns contiguous route planes, output and shared buffers; all input writes must precede reduction on the supplied stream. Launch performs no allocation or synchronization. It rejects unsupported geometries, null required pointers, unaligned pointers, route/output overlaps and partial shared/output overlaps; exact shared/output aliasing is supported. Offsets and grid strides use 64-bit arithmetic. Buffer lengths, residency and stream ordering remain unsafe caller obligations.

Standalone CUDA checks passed bit-for-bit against a sequential FP32/BF16 oracle on both local RTX GPUs and ostrich GB10, for rows 1/16/80/4096 in both supported geometries, with and without shared output. Checks include changed-input graph replay without allocation, exact shared/output aliasing, rejected invalid geometry/zero rows/overlap, and a cancellation case that fails if ranks are rounded before addition. The first multi-device fixture reused Torch's class-level default capture stream across devices; explicitly creating a capture stream on each device fixed the fixture without changing the kernel or comparison gates.

The M16 dSpark expert fixture also passed through the production Rust expert argument builder, C/AOT expert launch, Rust reducer handle and CUDA reduction on RTX 0, preserving relative-L2 < 0.01 and cosine > 0.9999 gates and changed-input graph replay without allocation. Python still prepares expert weights and scratch for this fixture. Both native architecture builds and the Rust daemon compile check passed (427 existing daemon warnings). Hashes and results are recorded in `ds41-native-route-reduction-qualification.json`.

This does not qualify network TP collectives, the production scheduler, native weight preparation, full containers, end-to-end serving, or four-machine checkpoint execution. Dodo was not used for this new reducer; prior SparkInfer arithmetic checks on dodo are separate evidence.

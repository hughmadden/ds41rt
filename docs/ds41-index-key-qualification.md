# Owned index-key projection and rotary normalization

The compressor source graph now produces the index key from the normalized, unrotated latent. It projects BF16 `[rows,512]` through the source's official BF16 `[128,512]` index weight, rounds the result to BF16, applies RMS normalization with `norm_eps=1e-20`, rounds again, and rotates the final 64 coordinates using the latent's first-token frequencies. This matches the ordering in the pinned reference indexer before FP4 encoding. The compressor latent remains unrotated for the later compressed-KV path.

The projection reuses the existing serialized cuBLAS handle and 4 MiB workspace. Native projection validation is shared with the compressor's existing path, retaining FP32 accumulation and disjoint-buffer checks. The norm operation now supports 128 dimensions, including optional rotation, while retaining the established 512/1280/5120 paths. Normalization rounding occurs before rotation at both supported rotary dimensions.

`CompressorWeights` additionally loads the real `indexer.wk.weight` and `indexer.k_norm.weight` tensors at layers 2/8/14/20. These eight BF16 tensors total 525,312 bytes across the four sources. `CompressorOutput` exposes the rotated BF16 index key alongside the unrotated latent, matching frequency rows and completed-row metadata, under the same lease/version checks and borrowed lifetime. Incomplete rows are still excluded by metadata. Neither proposal execution nor index-key generation commits a cache entry.

The expanded norm/RoPE qualifier passes 66 cases per GPU on both RTX PRO 6000 GPUs, including twelve 128-dimensional cases covering rows 1/16/80/255/1023/4095, tiny and zero inputs, changed-input graph replay, and the normalization-before-rotation boundary. The qualifier still reads and hash-checks the official inference epsilon. Existing norm, pure RoPE and fused KV cases also pass.

Both GPUs pass all fifty composed real-weight source-owner cases with the index-key consumer included. Forty-eight cases cover all four sources at 1/3/16 requests with changing activations, partial/zero acceptance, reordered chunks, stale-wave rejection and slot reuse. The remaining two cover 4096-row, sixteen-request prefill followed by partially accepted histories and replacement tails. Reference keys are independently generated from the reference compressor outputs, real index weights, explicit official RMSNorm and official rotary function. Maximum observed index-key absolute error is `.0078125`, within the existing `.004 + .016 * abs(reference)` BF16 tolerance. This is numerical agreement, not bitwise reference equality. Repeated index-key replay with unchanged inputs/state is byte-identical.

Index projection and normalized/rotated outputs add 512 device bytes per capacity row without another cuBLAS workspace. Wave totals are 5,485,824 bytes at 80 rows or 70,320,128 at 4096 for ratio two; ratio-one totals are 5,239,424 or 57,704,448. Combined compressor/index source weights occupy 10,618,112 bytes per ratio-two source or 5,375,232 for ratio one. Pending state and pinned metadata sizes are unchanged. Broader cache, driver, graph and model allocations remain separate.

Native, daemon and fixture builds pass. The adjacent JSON records source, reference-vector generator, fixture, result and real index-weight payload hashes. Temporary vectors remain under `/tmp/ds41-compressor-owner`. FP4 index-key encoding, compressed-KV rotation/encoding, persistent cache ownership, query-side indexing, hierarchical candidate selection, sparse attention and full-model execution remain unqualified or unimplemented. No throughput claim follows from these checks.

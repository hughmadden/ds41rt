# Hierarchical candidate blocks

The native hierarchy now implements the official eight-position block reduction, top-2048 block selection and expansion into 16,384 row candidates. `V41CandidateBlocks::maxima` consumes a contiguous score tile, its per-query first logical position and causal length. It masks unreachable rows, reduces each block by maximum score, and pins the newest reachable block to positive infinity. First positions must align to eight and tiles must partition blocks; only the last tile can end mid-block. Malformed metadata yields empty blocks.

`V41IndexTopK::update_blocks` accumulates the best 2048 block IDs across disjoint tiles, with the same reset/query-binding contract as row selection. It shares a fixed-K templated radix reduction with top-512. Block IDs are bounded below 131,072, corresponding to the official maximum history of 1,048,576 positions. Ties use the lower block ID, while finite source scores ensure the newest block's pinned infinity keeps it selected. The implementation does not claim PyTorch's particular choice among equal-scoring blocks.

`V41CandidateBlocks::expand` converts sorted selected blocks into U64 row positions, using `UINT64_MAX` for missing or unreachable rows. It clips the partially filled newest block to the query's causal length. The official helper can mark the remaining positions of that block in its Boolean mask; those positions are subsequently causally masked by index scoring. Qualification therefore compares the same reachable candidate set, intersecting the reference mask with causal bounds. Expansion produces unique reachable positions when selected blocks are unique.

Maxima and expansion allocate no workspace. Top-2048 scratch is `queries * ceil(block_candidates / 4096) * 2048 * 8 * 2` bytes, independent of total history. A 16,384-position score tile produces 2048 block maxima, requiring 32 KiB reduction scratch per query, plus 16 KiB carry and 8 KiB selected-block output. Expanded candidates occupy 128 KiB per query. The operator accepts up to 4096 queries; native score tiles are bounded at 16,384 positions. All operations run on the caller's stream and support graph capture. Native span/shape guards and Rust buffer/device checks apply.

`scripts/qualify-ds41-candidate-blocks.py` pins the official model/config hashes and executes the actual `select_candidate_blocks` function. Eighteen cases pass on each RTX PRO 6000 Blackwell: nine composed max/selection/expansion cases, eight larger direct top-2048 cases and one explicit tie/newest-block case. Pipeline shapes include widths 1/7/8/9/127/16383/16384, query counts through 4096 and three queries over 1,048,576 positions. The long case streams 64 bounded tiles and includes empty, complete and partially filled histories. Distinct block maxima give exact reachable masks against the official helper. Forward/reverse tile order yields identical accumulator bytes; captured replay after score changes agrees as well. Empty histories, malformed first positions/lengths/block IDs and native pointer/shape/scratch guards are exercised.

Direct top-2048 cases cover candidate counts 2047/2048/2049/4095/4096/4097/8193/16384, including odd merge counts. Untied selected sets match PyTorch top-k. The tie case checks the explicit lowest-block-ID policy and retention of the newest block. The existing 13-case top-512 qualifier also passes on both GPUs after templating the shared implementation, including million-position accumulation with forward, reverse and uneven partitioning.

The real-weight compressor fixture passes all 55 cases per GPU. Its four source-layer page-reuse cases now capture the entire chain: committed paged index scoring, causal block maxima, top-2048, expansion, a second scoring pass and top-512. Keys occupy logical pages in physical order `[1,0]`. Synthetic unit queries/head weights isolate cache addressing and selection from the still-unimplemented learned query producer. Histories of 257/258 rows select all reachable positions exactly, then a shrinking causal prefix and finally zero length produce the corresponding shortened/empty results from the same graph. This exercises the Rust wrappers, including an undersized maxima-buffer rejection. Actual pruning beyond 2048 blocks is established by the synthetic long-history reference cases, not this small real-weight fixture.

Native library, daemon and external fixture builds pass. Adjacent JSON records source/build/fixture/log hashes, reference results and the top-512 regression. Reusable qualifiers are tracked; the owner fixture remains outside Git under `/tmp/ds41-compressor-owner`.

These checks establish the hierarchy's numerical and addressing components. Production query projection/rotation/weight generation, candidate-source sharing across later layers, causal proposal overlays, persistent FP8 KV, attention, request-owned selection scheduling, full-model correctness and throughput qualification remain open. No full-model or speed claim is established here.
